# PG 指导采用闭环 v1 实验说明

本实验固定 `adaptive-pg-context-v2` 已实现的轨迹状态定位器、两跳六边局部图、种子程序图、Stable Kernel、求解模型、工具协议和独立核验器，只替换指导生成与采用观测方式：

- baseline `adaptive-pg-context-v2`：额外调用指导模型，把局部图改写成自然语言建议；
- candidate `adaptive-pg-context-v3`：不调用指导模型，直接把局部图编译成带稳定指纹的指导契约。

指导契约列出候选后继、边条件、建议、常见错误，以及紧邻的真实 `EMPTY/ERROR` 结果对应的决策指纹。候选后继只用于建议和采用审计；程序图不是权限系统，也不能强制 Agent 执行某条边。唯一硬阻断是参数、工具和动作完全相同且上一行动已经得到无进展结果的立即重放。改变查询参数、切换未完成目标、澄清、取得新证据或如实停止都不会被该规则误拦截。

离线契约使用：

```bash
venv/bin/python eval/run_pg_guidance_eval.py --gate
```

该 Gate 不调用模型，只证明编译、采用判定、精确重放阻断与开放式分歧边界符合冻结协议。它不能证明任务成功率提升。

PG13 已经参与 v2 和本轮问题选择，只能作为诊断回归。目录别名解析缺口已经在共享 Runtime 中独立修复，因此正式 v2/v3 对照必须在同一代码修订上运行，使两组都使用相同目录适配器。版本冻结后仍需建立未参与设计的新 holdout，才允许讨论任务收益；在此之前 v3 始终为 `candidate`。
