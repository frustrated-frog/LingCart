# PG：程序知识的结构演化

论文：[Procedural Graphs: Self-Evolving Execution Structures for LLM Agents](https://arxiv.org/abs/2609.09153)，2026-09-08 v1。作者项目当前题名为 Knowing What to Do: Self-Evolving Procedural Graphs for LLM Agents；核对的官方实现版本为 `9667bdc5f3fce89809429f9ce20188e3e989b9b3`。

## 要验证什么

多次执行的成败能否改变可复用的行动关系，并在未来任务上改善决策？PG 学习的是节点与关系及适用条件，和 ACE 的策略条目、每次任务的 TaskPlan、LivePlan 的在线纠偏分别装配。

实现保留论文的局部图指导、独立指导模型、增删结构、验证选择和拒绝记忆。没有引入作者的执行器、Provider 客户端或 embedding 服务。默认精确匹配最近行动、向外两跳、最近三步，未知行动回退全图。学习只离线发生，单次运行不修改图。

当前种子图由开发者编写，仅提供基本目标、检索、读证据、推荐、完成和澄清路径，**不是已学习的知识，也不是收益证据**。未覆盖的订单等行动仍由原 Agent 自主处理，Refiner 可以从训练轨迹扩展图。

## 冻结分组与选择

`evolution-spec.json` 将既有 adaptive dev 十个 case 按编号奇偶固定为五个训练、五个验证；每个 case 重复三次，共三轮提案。没有按已知结果选择样本。每轮用保留图重新收集训练轨迹，再提出修改；验证集只提供选择反馈，不把验证轨迹作为训练输入。test 不参与该循环。

每个候选必须结构合法、没有重复被拒绝的结构、验证成功率不下降、安全和协议违规为零、全部验证样本实际暴露过 PG 指导。模型调用额外增加最多每样本两次，同时每 Run 共用 16 次上限。验证相等可以接纳，这是论文选择规则；不等于统计显著改善或产品晋升。

原始训练/验证报告、Refiner 原始输出与调用事件、候选图、每轮选择及拒绝原因、最终保留图和候选 Profile 都保存，不覆盖。验证报告必须匹配图指纹、案例及重复次数、模型、预算、源码、依赖与业务环境。CLI 默认 dry run；`--live` 才调用公网模型。

## 运行

```bash
# 不调用模型
venv/bin/python -m eval.run_pg_evolution

# 显式真实 dev 演化：目录必须不存在
venv/bin/python -m eval.run_pg_evolution --live \
  --output-dir research/graphs/pg-run-001
```

真实演化最多执行 105 个 case 样本（15 个种子验证 + 每轮 15 个训练、15 个候选验证），另有三轮 Refiner（每轮至多两次模型尝试）；多轮 case 会产生多个 Run。建议先检查预算和模型配置。异常中断保留已有文件，不自动重跑收费步骤；当前版本不支持离线训练中断续跑，需审阅已保存产物后选择新目录。

完成后审查 `iteration-*-selection.json` 和候选 diff，把 `retained-profile.json` 复制到 `configs/harness/<文件内 profile_id>.json`。保留图仍为 candidate，禁止从 `/chat` 或 `/runs` 使用。不要改图文件原地覆盖旧版本。

在同一冻结代码与模型配置下，分别执行：

1. `adaptive-v1` 无 PG 的 test，三次重复、每 Run 16 次模型上限。
2. `adaptive-pg-context-v1` 固定种子图的 test，使用本目录 `experiment-spec.json` 与无 PG 报告对照。
3. 新生成 Profile 的 test，使用产物中的 `test-vs-baseline-spec.json` 和 `test-vs-static-spec.json`，分别与上述报告对照。

运行命令沿用 `eval.run_adaptive_eval --harness-profile <id> --split test --repeats 3 --max-model-calls-per-run 16 --output <report>`；候选 Gate 另外传 `--experiment-spec <spec> --baseline <report> --gate`。同一候选对两个契约分别运行会产生两份报告；需要重用同一份原始结果时应在离线 Gate 调用中替换契约，而不要声称重跑是同一实验。

正式 Gate 的保护项要求工具调用不增加，所有调用、Token 和延迟仍由 Runtime 原样报告；模型调用总成本另外受 Run 预算与离线选择契约限制。不要只报告 Solver 成本。当前 test 曾出现满分，可能难以测出收益；若要扩展挑战任务，应在演化前冻结新任务集与 split。

## 当前结论

工程与离线替身测试验证机制连通性，不代表真实模型收益。尚未运行真实 dev 演化、未冻结真实学习图、未进行 test 对照，没有 promoted Profile。负结果必须保留。

2026-10-23 工程验证：768 项 Python 测试、43 项前端测试通过；固定离线任务 Gate 60/60（71 轮）通过，前端类型检查和生产构建通过。新增端到端测试使用脚本模型与真实 SQLite/工具：种子图空检索后提前澄清，Refiner 提议恢复边，经验证保留后，新 Run 扩大检索并完成任务。测试还覆盖拒绝记忆、重复候选、分组污染、未知行动、结构错误、无暴露、成本/安全退化，以及响应已持久化但指导事件未写入的恢复窗口。

桌面验证使用临时数据库与脚本模型，通过真实 Durable Runtime、工程 API 和生产构建检查指导页；1280×720 下可展开局部关系条件和后续行动。临时运行不进入论文收益报告。
