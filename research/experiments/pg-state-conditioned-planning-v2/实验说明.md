# PG 状态条件规划同图对照 v2

本契约替代 v1 用于后续正式 V3/V4 对照。v1 两组默认 Profile 使用不同图产物，不用于归因条件筛选的独立收益；历史配置和报告保持原样。

## 固定与变化项

- baseline：`adaptive-pg-v3-shared-graph-v1`，机制版本仍为 V3，直接编译检索到的行动关系。
- candidate：`adaptive-pg-context-v4`，使用类型化条件筛选和目标进展/成本排序。
- 两组读取同一 `research/graphs/pg-seed-v2.json`；图路径、内容指纹、边条件、指导文字完全一致。V3 不求值类型化条件。
- 引擎、规划、记忆、核验、工具协议、轨迹定位、图跳数、上下文预算、局部边上限和定位阈值保持一致。
- V4 的信息增益事件是观测及排序反馈的一部分。本实验比较整个条件感知选择机制，不将结果单独归因于某一条件操作符或排序权重。
- 模型、Provider、调用预算、源码修订在每组实验开始前冻结，运行中不得变化；图指纹由现有 Harness manifest 记录并验证。

## 数据与结论

沿用未改动的 `eval/pg_state_condition_holdout_tasks.json`，开发集 2 项、留出测试集 4 项、每项重复 3 次。开发样本只检查流程；测试样本不得用于返调。PG13 不进入本契约。

必须使用同一源码版本上的两组完整报告及现有实验 Gate 判断。测试缺样、身份不一致、预算不一致、成本或安全回退均不能宣称收益。通过离线机制测试不代表真实效果；本修复没有运行计费模型，也没有 promotion。

运行入口为 `eval/run_live_eval.py`，通过 `--experiment-spec research/experiments/pg-state-conditioned-planning-v2/experiment-spec.json` 绑定契约，用 `--harness-profile` 显式选择上述基线或候选 Profile。正式启动前同时固定数据集、split、重复次数、模型预算、样本上限及输出参数；不依赖 CLI 的默认任务集或默认运行模式。
