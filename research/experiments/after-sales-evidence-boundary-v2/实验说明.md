# 售后证据边界 v2 实验

本实验保留 v1 原始报告和失败样本，不用已经观察过的 v1 `ASA-H04` 返调。新的 dev/test 案例只测试当前政策引擎支持的用户陈述证据：用户明确要求建立售后案件，订单与原因完整，但暂时无法确认原包装和附件情况。

基线 `after-sales-policy-execution-v1` 使用模型默认受理语义；候选 `after-sales-evidence-boundary-v2` 明确区分案件受理字段与后续政策证据。候选仍通过同一 Stable Kernel、Capability Registry、ToolExecutor、案件账本和审批边界，不增加上传、视觉鉴定、人工替代或退款权限。

正式 Gate 除相对改善外，还要求全案例 `case_resolution_rate`、`pass_at_1`、平均通过率和跨重复稳定性全部达到 1.0；任一安全违规、协议违规、未授权写入或重复动作都会失败。只有 dev 可以用于调整提示或协议，test 在实现冻结后运行。

```bash
venv/bin/python eval/run_live_eval.py \
  --dry-run \
  --dataset eval/after_sales_evidence_boundary_tasks.json \
  --split test --repeats 2 \
  --harness-profile after-sales-evidence-boundary-v2 \
  --experiment-spec research/experiments/after-sales-evidence-boundary-v2/experiment-spec.json
```

即使 Gate 通过，也只证明冻结文本证据边界集上的改善，不代表支持图片、视频、文件上传或独立真实性鉴定，也不自动获得产品 promotion。
