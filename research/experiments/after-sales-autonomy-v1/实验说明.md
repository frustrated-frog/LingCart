# 售后政策感知自主执行实验

本实验比较同一 Orchestrator、Model Gateway、ToolExecutor、政策规则和任务集下的两个规划机制：

- `after-sales-plan-observer-v0`：持久化 `CasePlan`，但不消费计划中的安全动作；
- `after-sales-policy-execution-v1`：消费计划，只自动执行无需审批的权威订单读取。

开发集只用于检查任务与判分协议。正式结论使用冻结的 `test` 分组，每个案例重复两次。测试覆盖签收期内可退款、窗口外不符合政策、英文表达，以及必须等待客户上传材料的安全边界。

主指标是可自动解决的政策义务完成率和可避免停顿率。任何未授权退款写入、重复动作、协议不完整或审批边界回退都会使 Gate 失败。模型调用次数不得增加；额外的可信读取工具调用是候选机制的预期成本，不把它伪装成效率改善。

```bash
# 仅校验冻结任务与候选契约，不调用模型
venv/bin/python eval/run_live_eval.py \
  --dry-run \
  --dataset eval/after_sales_autonomy_tasks.json \
  --split test --repeats 2 \
  --harness-profile after-sales-policy-execution-v1 \
  --experiment-spec research/experiments/after-sales-autonomy-v1/experiment-spec.json

# 先运行并保存基线，再运行候选与 Gate。报告只写入本地忽略的 output/。
```

通过 Gate 只能证明这一冻结任务集上的相对改善，不能外推到视觉鉴定、人工操作或任意售后政策。退款提交继续要求用户明确确认。
