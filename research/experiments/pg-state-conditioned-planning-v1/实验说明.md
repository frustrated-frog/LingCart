# PG 状态条件规划 v1 实验说明

> 历史契约：本版本两组默认 Profile 使用不同图产物，不能将结果单独归因于条件筛选。后续正式对照使用 [同图对照 v2](../pg-state-conditioned-planning-v2/实验说明.md)，本契约保留用于解释历史配置。

本实验只比较一个主要算法变量：V3 检索出的局部图是否经过“受限类型条件 + 当前可信轨迹证据 + 目标进展/成本排序”筛选。Stable Kernel、求解模型、工具、预算、目标账本、独立核验器和确定性指导契约全部固定。

- baseline：`adaptive-pg-context-v3`，定位后将检索到的一跳行动关系直接编译为建议；
- candidate：`adaptive-pg-context-v4`，仅把条件求值为 `TRUE` 的当前边编译为建议，`FALSE` 与 `UNKNOWN` 均不进入行动集合；
- 两组运行在同一源码修订上，因此工具 schema 校验、目录别名归一化身份和执行前重放保护完全相同；
- V4 额外记录指导后的真实目标进展，这只是观测证据，不能直接当作收益。

`eval/pg_state_condition_tasks.json` 是零模型调用的机制 Gate，只证明协议边界。旧 PG13 只作回归诊断，不进入正式结论。正式对照使用新冻结的 `eval/pg_state_condition_holdout_tasks.json`：开发集可以检查流程，测试集只有在 Profile、图、阈值和实现冻结后才能运行，且不得用于返调。

离线 Gate：

```bash
venv/bin/python eval/run_pg_state_condition_eval.py --gate
venv/bin/python eval/run_pg_guidance_eval.py --gate
```

真实模型对照必须由用户显式启动，使用相同 Provider、Model、重复次数和预算，保存全部负结果。没有完成三次重复且测试集身份、源码指纹、模型配置和预算不可比时，结论只能是 `INCONCLUSIVE`；本提交不包含任何真实模型收益声明。
