# ACE 决策效率与新留出集说明

## 样本身份调整

`ACE-C01` 已经用于首次 Smoke、根因分析和本轮机制设计，因此从该时刻起只能作为诊断样本，不能再称为盲测或用它支撑 promoted 结论。旧文件和结果摘要继续保留，保证历史可追溯，不删除负结果，也不改写当时的实验口径。

新的 `eval/ace_efficiency_tasks.json` 明确分为：

- 3 个 `dev`：用于检查已知三模/静音轴链路、数量单位与否定极性，以及未注册语义的安全回退；
- 4 个 `test`：冻结新的键盘、耳机和扩展坞组合。本轮只校验数据与契约，不运行真实模型，也不根据 test 结果修改实现。

正式对照使用 `efficiency-experiment-spec.json`。旧 `challenge-experiment-spec.json` 只用于解释历史报告，不再作为下一轮 promotion 契约。

## 结论边界

离线测试已经证明协议和恢复语义，但不能证明真实模型会稳定选择正确 concept，也不能证明 ACE 上下文带来收益。后续付费评测仍按以下顺序执行：

1. 对 dev 做 `--dry-run`；
2. 仅选一个 dev 样本、一次重复、每 Run 最多 6 次模型调用；
3. 检查 concept、事务、独立审查、动作面和最终新鲜度证据；
4. Smoke 无协议或安全问题后，才冻结 Baseline 的完整 test 报告；
5. Baseline 没有天花板时再运行 Candidate；
6. 不查看单个 test 结果后修改 Prompt、Playbook、codec 或动作面。

本轮没有调用真实模型，因此没有新增成功率、Token 或延迟收益声明。
