## 成本控制

`eval/run_semantic_live_eval.py` 默认只执行 Dry Run。真实请求必须同时满足：

1. 显式传入 `--live`；
2. 指定不存在的 `--output` 路径，拒绝覆盖历史报告；
3. 计划执行次数不超过 `--max-executions`；
4. 每次运行不超过 `--max-model-calls-per-run`；
5. 受版本控制的文件没有未提交变化。

推荐先预检：

```bash
venv/bin/python -m eval.run_semantic_live_eval \
  --case trusted-timezone-normalization \
  --mode auto \
  --dry-run
```

单案例 Smoke：

```bash
venv/bin/python -m eval.run_semantic_live_eval \
  --live \
  --case trusted-timezone-normalization \
  --mode auto \
  --repeats 1 \
  --max-executions 1 \
  --max-model-calls-per-run 2 \
  --output output/semantic-live-smoke-<commit>.json
```

不要在没有先查看 Dry Run 中 `planned_executions` 和 `worst_case_model_calls` 的情况下提高预算。

## 后续验收

专项数据集已扩充到 22 个案例、11 个风险组，并支持跨轮历史、目标数量、实际工具与禁用工具断言。风险组可以单独预检：


分阶段预算和 Gate 固定在 `acceptance-spec.json`。后续真实模型按以下顺序执行：

1. 单案例 Smoke，确认 Provider、结构化协议和评分器可用；
2. 每类风险选择一个代表案例，执行一次低成本覆盖；
3. 只有代表案例没有暴露系统性缺陷时，才运行完整 Auto 基线；
4. Auto 基线稳定后，再对小型一致性子集运行 Adaptive；
5. 最后才考虑重复试验，不允许直接运行完整数据集的多模式多重复组合。

正式验收报告必须保留数据集、提交、模型配置、执行预算、原始结构化 Understanding、Plan、Provider 证据、工具和目标完成状态。
