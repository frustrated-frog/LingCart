## V2 目标级 Oracle

数据集和验收契约已经升级为 schema V2。评测不再只检查“目标类型或工具名是否出现”，而是为每个用户
目标冻结独立 Oracle，并沿以下证据链一对一核验：

`objective -> normalized entity -> capability -> paired tool event -> authoritative result -> goal outcome -> terminal`

两个同类目标不能再按数量通过。例如“纽约和伦敦分别几点”必须匹配两个不同时区目标和两组正确参数的
`read_clock` 调用/结果；“你是谁，能做什么”必须同时产生 `IDENTITY` 和 `CAPABILITIES`。禁用操作从
物理事件检查，即使它没有出现在展示用 trace 中也会失败。Auto/Adaptive 一致性比较目标、实体、结果和终态
投影，不再只比较顶层状态字符串。

Gate 分为三个不可互换的机器契约：

- `SmokeGate` 只证明冻结的小样本链路可用，结论范围固定为 `selected_cases_only`；
- `AcceptanceGate` 要求阶段的完整 case × repeat × mode × Profile 网格，不接受临时子集；
- `ExperimentGate` 只接受两个已经通过的 Acceptance 报告，并检查数据集、模型、预算、环境与依赖身份。

## 成本控制与故障恢复

`eval/run_semantic_live_eval.py` 默认只执行 Dry Run。真实请求必须同时满足：

1. 显式传入 `--live`；
2. 指定不存在的 `--output` 路径，拒绝覆盖历史报告；
3. 选择 `acceptance-spec.json` 中的冻结 `--stage`；
4. 计划执行次数不超过阶段预算；
5. CLI 预算只能进一步收紧，不能扩大阶段或 Runtime 默认上限；
6. 后续阶段提供同一数据集/契约下通过的前置报告；
7. 受版本控制的文件没有未提交变化。

真实运行在第一次模型调用前创建 `<report>.journal.jsonl`。每个样本先写 `SAMPLE_STARTED` 并 fsync，完成或
异常后写唯一的 `SAMPLE_TERMINAL`。记录使用连续 sequence、前向哈希链和进程文件锁；完整但损坏的记录会
失败关闭，只允许恢复未换行的最后一段未提交字节。续跑会核对数据集、阶段、Profile、模型配置、预算、源码、
依赖和样本计划的统一身份；身份漂移时在模型调用前拒绝。已经有终态的成功、失败和异常样本都不会重跑，
避免从多次付费尝试中挑选最好结果。

推荐先预检：

```bash
venv/bin/python -m eval.run_semantic_live_eval \
  --stage single-smoke \
  --dry-run
```

单案例 Smoke：

```bash
venv/bin/python -m eval.run_semantic_live_eval \
  --live \
  --stage single-smoke \
  --max-model-calls-per-run 2 \
  --output output/semantic-live-smoke-<commit>.json
```

中断后只能在身份完全相同时显式续跑：

```bash
venv/bin/python -m eval.run_semantic_live_eval \
  --live \
  --resume \
  --stage single-smoke \
  --max-model-calls-per-run 2 \
  --output output/semantic-live-smoke-<commit>.json
```

不要在没有先查看 Dry Run 中 `planned_executions` 和 `worst_case_model_calls` 的情况下提高预算。

## 后续验收

专项数据集包含 22 个案例、11 个风险组，并支持跨轮历史、目标级实体、规范化参数、实际工具事件与禁用操作
断言。临时风险组选择只能形成 `ad-hoc-smoke`，永远不能产出 Acceptance 结论：

```bash
venv/bin/python -m eval.run_semantic_live_eval \
  --group negation \
  --max-cases 2 \
  --dry-run
```

分阶段预算和 Gate 固定在 `acceptance-spec.json`。后续真实模型按以下顺序执行：

1. 单案例 Smoke，确认 Provider、结构化协议和评分器可用；
2. 使用 `risk-sample` 阶段，并通过 `--prerequisite-report` 绑定已通过的 `single-smoke` 报告；
3. 只有代表案例没有暴露系统性缺陷时，才运行完整 Auto 基线；
4. Auto 基线稳定后，再对小型一致性子集运行 Adaptive；
5. 最后才考虑重复试验，不允许直接运行完整数据集的多模式多重复组合。

正式验收报告必须保留数据集/案例/阶段/Oracle/Profile/源码/依赖/模型配置指纹、有效预算、原始事件、
结构化 Understanding、Plan、Provider 证据、工具结果和逐目标判定。API Key、认证头、原始 Provider 异常
与动态健康状态不得进入报告身份或 Journal。
