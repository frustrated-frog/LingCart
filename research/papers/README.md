# Paper Lab

这里保存“论文技术 → 可运行机制 → 真实消费任务证据”的完整链路，而不是论文名称清单。

每次实验建立一个独立目录，至少包含：

- `paper-spec.yaml`：论文来源、工程假设、作用层、对照 Profile、候选 Profile 与成功/退出标准。
- `notes.md`：复现过程中发现的实现差异、论文未覆盖的工程边界与失败记录。
- `results/`：由统一评测入口生成的原始报告和聚合结果；不得手工改写指标。
- 对应的 `configs/harness/<profile>.json`：只有真正可运行的机制才注册为 Profile。

接入流程保持开放，不固定论文名单：发现新工作后先写可证伪假设，再实现最小机制；用冻结任务、相同模型、相同预算和相同评测协议做对照。有效机制可以升级为 `promoted`，无收益或有副作用的机制保留结果与退出原因，不包装成成功案例。

复制 [`../templates/paper-spec.yaml`](../templates/paper-spec.yaml) 开始一次实验。当前 `baseline-v1` 与 `adaptive-v1` 是真实现有执行路径的冻结对照，不代表未来论文方向。
