# 多轮理解与恢复二版验证记录

## 实现范围

两个候选保持独立变量：`after-sales-source-refs-v1` 相对目标修订版只改变引用协议；`after-sales-control-intent-v1` 在引用协议候选之上只改变控制语义规划。均为 candidate，产品入口拒绝直接使用。

宿主将本轮 HUMAN 原文切成带 Run、消息与范围身份的片段，模型返回引用 ID，持久化仍保留精确原文。引用匹配不等于材料充分，后续材料归属和政策核验继续独立运行。现有案件中的等待确认、明确禁止、解除指定禁令与撤回旧确认分别解释；没有增加模型调用、重试或上下文上限。

控制语义必须与独立需求提取一致。明确禁令可先收窄权限；放宽限制需完整通过核验。CASE 范围通过会话账本绑定案件和订单，SESSION 范围作用于整个会话。撤回的确认身份持久化，在重放、preflight、执行以及旧确认恢复展示前检查；后续重新核验可以取得新确认。

## 保留的开发负结果

- `run-01`：评测汇总错误要求旧案例存在可选的最终状态字段。首条轨迹完成但未保存完整原始结果，保留日志并明确不能比较收益。增加汇总兼容回归，并确保后续即使回调失败也保存已有样本。
- `run-02`：完整旧版组及部分引用组暴露多次 `SOURCE_REFERENCE_UNKNOWN`；诊断发现引用转换没有保留可空字段契约。修复后依然出现该错误，因此不能将全部失败归因于 null。保留全部已保存样本和中断原因。
- `run-03`：真实输出证实模型把原文句子填入引用 ID。原模板既要求 ID 又要求精确原文子串，存在冲突。只统一模型侧协议说明，不将任意文字宽松转换成合法 ID；修复后重新冻结源码。该轮单条 smoke 与带观测的诊断均不计入正式对照收益。

所有以上诊断只使用 dev；冻结的三项 test 表达变体尚未在这些迭代中使用。原始负结果位于 `research/experiments/after-sales-control-intent-v1/run-01` 至 `run-03`。

## 最终冻结对照

最终源码为 `0c81d09`。同一模型配置、数据、上下文与调用预算下，三组依次执行既有五项 dev 场景和三项冻结 test 表达变体，每项重复两次。每个 Run 最多 8 次模型调用，每次 Provider 最多尝试一次；16000 字符、45 秒、Token 与工具预算保持原值。

判定基于每轮任务结果、实际工具返回中的本轮入账材料和恢复后的新确认身份。完整结果与比较文件保存到 `research/experiments/after-sales-control-intent-v1/run-04`；已保存全部 48 条多轮轨迹；六份报告的源码树、模型配置、预算及原始报告 SHA-256 已核对一致，完整报告逐项包含进度副本的原始样本后，去除了重复 jsonl。

模型为 `openai_compatible / deepseek-flash`。以下是冻结源码 `0c81d09` 的完整轨迹通过数，任一关键轮次失败即整条失败。

| dev 模型调用 | 102 | 103 | 112 |

**结论：实现了新能力，但尚未证明在复杂多轮表达上获得稳定成功率收益，不能晋升。** dev 通过数小幅增加，未泛化到三项留出表达变体；调用次数分别增加，两个正式 Gate 均未通过。不放宽成本门槛，不用中间步骤成功替代完整任务成功。

原文引用版剩余失败包括 16000 字符上下文耗尽，以及恢复后仍保持禁止提交的解释。控制语义版剩余失败包括控制枚举或字段组合不合法、材料入账前进入澄清、恢复后政策核验仍未满足；不能依靠 UI 展示或脚本模型测试掩盖这些失败。

真实模型轨迹中观察到 `REQUIRE_CONFIRMATION`、`PROHIBIT` 和 `RELEASE_PROHIBITION` 被接受；`REVOKE_APPROVAL` 本轮由自动化与浏览器脚本验证，未获得独立真实模型任务成功证据。控制候选同时包含紧凑的目标元数据投影，因此不能把整个候选的差异单独归因于控制分类名称。

此处轨迹完整性指标不统计模型 JSON 格式错误；后者已经按任务失败计入通过率。

引用实验的正式 Gate 还指出缺少统一的 `mechanism_applied` 事件。原有 `request_sources_resolved` 已记录真实调用，但不满足 Gate 的统一事件契约；该缺陷不通过补写历史事件修正，原始失败报告保持不变。

## 评测后的工程收尾

不修改留出用例或根据留出语言调参。只补齐引用解码实际执行时的统一机制事件，并修复同一订单多案件的范围匹配：有明确案件 ID 时按案件匹配，只有不带案件 ID 的直接订单工具才回退到订单保护。明确的其他案件不会被错误撤回确认或套用另一个案件的禁令；直接退款也不能绕过案件限制。

这两项是评测之后的兼容与可观测性修复（实现提交 `1a16717`），最终源码指纹与 `0c81d09` 不同。上表只能说明已冻结版本的效果，不能当作收尾版本重新通过完整实时评测的证据。自动化覆盖同订单不同案件、旧授权匹配、直接订单工具保护、真实引用机制事件及崩溃恢复。产品仍不启用候选。

## 限制

两次独立输入的解释仍使用同一模型配置，可能发生共同误解。新控制语义主要覆盖已有案件的多轮修订；本轮真实模型数据以单案件为主，多案件和长历史泛化仍需更多证据。短样本延迟差异不代表稳定性能收益，Token 未完整报告时不能推算成本；没有验证价格时不估计货币支出。

离线回归只证明工程不变量，不保证开放任务成功率。候选不会因局部样本通过自动晋升，保留模型调用不可增加的成本门槛。
