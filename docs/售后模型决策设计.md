# 售后模型决策设计

本阶段基于 `5ee9892`，在现有 planning 槽增加模型驱动的下一步决策。用户目标、真实观察和合法动作共同进入模型；模型选择一个动作或澄清目标，真实执行后重新决策。

## 不变量

- 用户原文、独立需求契约、政策义务和真实材料分别提供；模型不能修改已保存的事实、政策或授权。
- 模型只选择当前状态下合法的动作身份，工具名、参数、案件版本和确认要求由宿主编译。
- 目标方向不明确时可提出目标澄清，此时不生成提交确认，不把问题绑定为某份材料的回答。
- 模型只提出当前一步；预计观察和重新规划条件是建议，不是未来已经发生的事实。
- 同轮工具结果更新后重新规划；恢复仍复用 Runtime 模型缓存和工具账本。恢复输入不依赖可变化的事件数量或 SUCCEEDED/REUSED 标记。
- 每次决策最多一次协议修复，与既有调用、上下文、工具和时间预算共用上限。非法输出不能进入执行。
- 新 Profile 保留 candidate，只替换 planning；以统一材料协议候选为同版基线，完整保存负结果。

## 第一版范围

支持现有售后能力提供的查询、材料澄清、延期等待、确认请求和能力阻塞。模型可以改变合法动作的选择顺序，或因用户目标不匹配而暂停澄清。新业务能力仍须通过能力注册与工具实现接入；模型不能凭空执行维修等尚未注册的操作。

本阶段建立真实的模型决策位置及其可观察反馈，不同时修改 ACE/PG，也不宣称已经实现经验自学习。
