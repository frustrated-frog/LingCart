# 复杂任务语义与修订闭环设计

## 问题与范围

既有 RequestIR 是已接受目标的投影。它能检查编译结构，却不能独立发现规划模型遗漏的数量或错误的条件范围。运行中修改又会清空目标账本，普通跨轮也主要依赖模型重新阅读历史。

本次在 Adaptive 深度任务链路引入独立需求契约。提取器只读 HUMAN 原文和先前需求，不读取待审目标、工具输出或规划解释；随后与目标逐项比较。原有独立审查和最终证据核验继续保留。普通对话不冒充经过同样的全量语义比较，但使用共同工具边界执行结构化禁止操作。

## 不变量

1. 独立语义契约与可执行目标必须双向覆盖结果、数量、目标及条件范围；编译不一致不能执行工具。
2. 每个旧要求都必须明确声明 `PRESERVE`、`REPLACE` 或 `RETRACT`；新要求使用 `ADD`。保留操作由宿主复制旧内容，不能夹带编辑。
3. 替换和撤销必须引用本次 HUMAN 修改原文；不能用拼接请求中的旧指令授权新变化。
4. 条件引用有效结果身份；撤销结果不能留下悬空条件。所有原文位置由宿主生成。
5. 仅保存用户要求及来源用于跨轮继承；业务事实仍来自工具。旧候选不等于当前已核验结果。
6. 修订只让受影响目标失效，保留其他目标和候选线索；历史事件与副作用账本不可删除。最终推荐继续刷新价格、库存与约束。
7. 禁止操作在统一 ToolExecutor 检查，优先于已有确认；解除禁止也不构成支付或退款授权。
8. 提取调用使用既有 Model Gateway、共享预算及持久化模型重放；失败不回退成无约束执行。

## 验证边界

确定性测试验证契约、编译、修订和恢复行为，不证明模型能正确理解所有自然语言。真实模型效果需另行保存原始轨迹并评估，不能把单元测试通过写成复杂任务准确率保证。

## 执行链路与恢复

新 Adaptive 检查点使用 schema 8。规划器提出目标后，独立提取器只读取本轮 HUMAN、历史 HUMAN 与旧需求；模型上下文注入被隔离，调用仍经过统一 Gateway 和共享预算。提取器支持 JSON 及原生严格工具协议，最多一次格式修复。提取成功后先持久化契约及模型游标，再比较目标；规划修复复用同一份提取结果，不能反向改写它。

编译器匹配结果类型、数量、订单或比较目标，以及每个商品条件对应的结果集合。相同条件允许使用相互重叠的 HUMAN 原文片段，但不能跨原消息绑定。目录概念与品类别名经现有可信注册表归一化，不为具体问句增加比较特例。未明确要求进入澄清；协议错误、来源错误、目标缺项与新增条件都有机器可读原因。

运行中 STEER 保留旧候选及证据引用作为线索，只使受影响目标失效；保留要求也不复用旧完成收据。完成后的下一轮从持久会话继承需求契约，但价格、库存等业务状态仍重新查询。旧 schema 4–7 检查点继续使用历史冻结协议，不补造独立提取记录。

## 执行限制

`READ_ONLY` 阻止业务写操作，`NO_PAYMENT` 和 `NO_REFUND` 分别阻止支付及退款，`NO_SUBMISSION` 阻止最终提交但允许准备本地草稿。普通对话与 Adaptive 使用同一限制存储及 ToolExecutor 检查；生成付款、退款或案件提交的确认提案之前也进行检查。已有审批、工具账本缓存或后续任务都不能覆盖限制。

解除限制必须引用本轮 HUMAN；解除不等于授权。普通对话解除 Adaptive 中产生的限制时，同时显式撤销旧契约对应条目，避免后续 PRESERVE 重新启用旧限制。重放解除请求保持契约身份稳定。无法解析已保存限制时明确失败，不能默认为允许。

## 控制台投影

Run Inspector 的“上下文与证据”增加“需求与修订”：按结果展示目标数量、原文、专属或共享条件，以及保留、替换、撤销和新增记录。分别展示“已提取待匹配”“已匹配执行目标”“已保存修订但未执行”，不把候选提取画成已接受结果。旧运行显示缺少独立契约的真实空态。限制列表来自后端已持久化状态。

## 已知边界

- 多一次独立提取通常增加一次模型调用；有格式修复或目标修复时更多，仍受既有预算限制。
- 提取器与规划器可以使用同一模型服务，并非彼此统计独立的真值判定器；两者仍可能同时误读原文。
- 普通对话具备统一执行限制，但没有声称覆盖全部结果、数量、范围的独立提取比较。
- 当前 Adaptive 目标不能表达跨商品总价等聚合条件时，应保留 UNKNOWN 并澄清，不能偷偷改成单件预算。
- 历史 HUMAN 不能容纳于上下文预算时明确停止，不靠裁剪原始条件维持表面成功。
- 过程要求可保留为上下文边界；本轮确定性编译覆盖结果、数量、目标和商品条件，不声称已经为任意排序、格式等交付指令提供求解器。

## 真实运行暴露的接入修复

1. 严格工具 schema 的压缩只能删除 JSON Schema 注解，不能删除 `properties.description` 这种实际必填字段；新增测试检查真实发出的工具声明。
2. 提取器必须明确说明类型判别规则、条件作用范围和同一条件原文的一致性；格式反馈只保留字段路径与错误类别，不回显完整模型输入。
3. 目标审查读取单独保存的流程要求与禁止事项，并把该契约身份计入审查依据。审查器仍对照 HUMAN 原文判断，不能把另一模型的分类当成真值。
4. `quantity`、不同商品身份、全部推荐的交付与最终价格库存刷新由 Runtime 执行，不因审查器不了解这些规则而增加无意义商品谓词。
5. 目标通过语义匹配后，审查器引用错了来源属于审查协议错误。新检查点在审查器内部检查引用对齐，并使用既有一次有界格式重试；不能把引用错误转成规划器改写用户目标的指令。
6. 已成功提取的禁止事项立即收窄持久权限；业务目标澄清或失败不能丢失禁止要求。候选修订不能提前解除旧限制，放宽仍等待接受阶段。
