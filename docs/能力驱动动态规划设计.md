# 能力驱动动态规划设计

## 目标与不变量

借鉴 CGAP（arXiv:2610.41040），在现有 Adaptive 引擎的 planning 槽位增加声明式能力规划。模型负责理解目标、提供无法确定性绑定的参数和最终交付；规划器从工具契约搜索前置依赖，已具备可靠参数的只读步骤可以直接交给现有执行内核。

实现前冻结以下不变量：

- 不新增 Runtime；所有真实工具仍经过原有 schema、权限、预算、deadline 和工具账本。
- 规划预测不写入业务事实。只有已验证的实际观察可以满足前置条件；空结果、失败、缺字段不算提供了预期输出。
- 订单事实按订单编号隔离；目标、参数和证据保持可追溯。用户修改目标后重新投影，不复用旧规划状态。
- 已完成步骤不可重写。每次观察后只重新搜索未完成部分，保留历史计划与变更原因。
- 规划器不宣布任务完成。推荐、约束核验、完成声明与独立审查继续由既有路径执行。
- 搜索有节点与长度上限；无解、未建模能力和参数缺失显式呈现，不能猜测授权或事实。
- 新 Profile 保持 candidate，仅从研究入口运行。离线测试只证明机制和回归边界，不代表真实模型收益。

## 工程范围

第一版采用有界状态空间搜索实现论文的能力编译思路，不引入外部 PDDL 运行时。注册输入、输出与语义前置条件是应用提供的工具契约，不从自然语言自动推断业务规则。保留模型对商品检索参数、推荐与开放式恢复的决策职责。

## 在线执行

`CapabilityRegistry.planning_contracts()` 暴露工具语义契约，扩展能力可随注册项提供自身契约。输入 schema 与只读策略来自既有 ToolSpec。规划器按已接受目标绑定订单编号或问题，合并相同工具/对象/参数的动作，对多目标共同搜索最短依赖路径；最多 128 个动作、2048 个搜索状态，步数继续受剩余 Runtime 预算限制。

每个决策边界从 `TaskPlan` 中重新投影已验证观察。零值和否定结果是合法事实；空结果、业务错误、对象不匹配或旧目标修订的观察不建立前置事实。订单按编号隔离，问题按内容身份隔离，商品候选是共享检索观察，具体推荐约束和对比对象仍由现有校验负责。

只读步骤参数完整时生成普通 `Decision(action=tool)`，并经过既有参数校验、PG 审查、ToolExecutor 与核验。无法自动绑定的商品动作留给模型。提交步骤时再次核查语义前置条件，并把实际来源步骤写入 `depends_on`。不执行整个预测序列，每次真实观察后重新求解。

`capability_plan_updated` 持久化计划身份、工具契约指纹、版本、剩余节点、真实事实来源、缺失能力和搜索状态。检查点保留当前投影；已接受 pending 动作恢复时沿用原有账本，不重新选择另一个动作。用户改变目标后从新的步骤边界重新收集观察。

## 前端与接口

`GET /engineering/runs/{run_id}` 新增 `capability_planning` 投影（Pydantic 协议），包含历史版本、部分记录状态与目标过期标记。运行检查的“能力规划”页据此绘制真实依赖图，不把预测的提供项画成已完成成果。缺失记录、解析错误和过期目标分别呈现。旧运行返回空投影，无需数据库迁移。

## 边界

当前目标种类沿用 Adaptive 协议，未新增跨商品总预算或基于原商品自动提炼替代条件的语义。目标解释错误仍可能导致规划错误，规划器不会取代独立语义审查。CGAP 观察获取计划不是业务完成证明；正式结论与候选晋升需另行真实模型对照。详见论文接入说明与冻结实验契约。
