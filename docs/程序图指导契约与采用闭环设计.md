# 程序图指导契约与采用闭环设计

## 为什么需要第三版

v2 已解决“从哪里取图”，但真实诊断暴露了新的边界：指导器本身会消耗和求解器相同的模型预算。PG13 中三次指导调用占用了三次模型额度；Agent 最终已经找到候选并查到退货政策，却没有额度继续读取完整证据、推荐和完成独立审查。同时，过去只能在事后按边目标推测 Agent 是否采纳建议，无法区分“模型看到了但偏离”“候选被内核阻断”和“根本没有下一次决策”。

v3 冻结 v2 定位器和程序图，只替换指导生成与采用审计变量。

## 确定性指导契约

`PGContextEngine` 将已检索的局部子图直接编译为不可执行的数据契约：

- `contract_id`：覆盖图指纹、定位结果、采用边和重放约束；
- `recommended_actions`：局部边直接指向的已注册行动节点；
- `instructions`：边编号、来源、目标、自然语言条件、指导与常见错误；
- `forbidden_repeats`：紧邻的真实空结果或错误对应的完整决策指纹；一旦有其他行动推进状态便不沿用旧阻断；
- `policy`：`ADVISORY_EXCEPT_EXACT_NO_PROGRESS_REPEAT`。

编译过程不调用模型，不解释或执行边条件，也不把图当成事实、权限或授权。自然语言条件仍由主 Agent 结合当前目标和真实证据判断，因此未知条件不会被内核假装成布尔表达式。

## 提交前采用审计

模型返回候选决策后、工具执行前，Runtime 使用同一契约生成 `pg_decision_reviewed` 事件：

- `ALIGNED`：实际行动命中候选后继；
- `DIVERGED`：存在候选后继，但模型选择了其他行动；只记录，不强制改写；
- `UNKNOWN`：局部图没有直接行动后继，不能判断；
- `BLOCKED`：决策指纹与已有 `EMPTY/ERROR` 调用完全相同，提交前拒绝。

阻断只比较结构化动作、工具及全部参数的内容指纹。更换查询词、调整有依据的过滤条件、推进另一目标或停止都会产生不同指纹。被阻断的决策不进入 ToolExecutor，不占工具预算，也不会被伪装成模型协议错误；Runtime 将机器可读反馈交给下一次决策。

## 持久化与恢复

指导事件、契约、采用审查和拒绝事件都进入执行事件链。契约身份由冻结图与轨迹状态决定；同一模型响应在恢复后复用相同审查记录。历史 v1/v2 事件没有契约字段时仍按旧证据投影展示，不反向伪造采用状态。

## 指标与研究边界

新增指标包括确定性契约数、指导模型调用数、采用对齐、采用分歧和无进展重放阻断数。离线 Gate 固定七种状态，要求全部契约判定通过且指导模型调用为零。

这些指标只能证明机制按设计工作。候选 Profile 仍需与 v2 在相同代码、模型、预算和未见任务上重复对照；成功率、恢复率、工具调用、模型尝试和 Token 必须共同报告。PG13 已参与设计，只能作为诊断样本，不能用于宣称无偏收益。
