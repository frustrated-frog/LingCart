# 政策感知自主执行设计

## 目标与范围

本轮把已经持久化的售后 `CasePlan.next_actions` 接入真实执行链，使 Agent 能在退款案件中自动完成政策允许、无需用户授权的权威业务取证，再根据新证据重新裁决和规划。它解决的是“计划已经知道下一步，但运行时仍停下来让用户代替系统查询”的问题，不引入第二套 Runtime，也不把流程写死成新的政策引擎。

V1 只自动执行一类动作：政策要求的未满足义务允许 `ORDER_RECORD` 来源、核验条件为 `AUTHORITATIVE_ORDER`，并且持久计划明确给出无需审批的 `continue_after_sales_case`。客户陈述、图片鉴定、人工复核和退款提交都不在自动动作面内。

## 执行链

```text
prepare/continue_after_sales_case
  -> Case State Projector
  -> Policy Obligation Verifier
  -> 选择一项持久化 CasePlan 动作
  -> 同一 ToolExecutor 执行可信读取
  -> 校验输出与案件修订号进展
  -> 重新投影、裁决和规划
  -> 在补充材料、明确确认、能力边界或预算边界处暂停
```

`src/after_sales/execution.py` 提供三个有稳定版本的确定性组件：

- `policy-aware-case-state-v2` 把案件修订号、有效政策裁决、政策校验和、最新有效计划、义务与下一步动作绑定为不可变状态，并生成稳定 `state_id`。
- `policy-obligation-verifier-v2` 检查目标义务是否仍未满足、来源是否为权威订单、操作是否与计划一致，以及是否要求审批。
- `policy-aware-next-action-v2` 只在上述检查全部通过时生成执行指令；身份过期、动作伪造或未知路径都主动弃权。

每个动作仍通过 Stable Kernel 中已有的 `ToolExecutor`，共享 schema 校验、预算、deadline、工具账本、错误归一化与恢复语义。自主循环最多执行四项动作，并进一步受当前 Run 剩余步骤预算限制。工具结果必须通过能力输出契约，且案件修订号必须单调增加；否则以 `CASE_AUTONOMOUS_NO_PROGRESS` 失败关闭。

## 安全与恢复不变量

- 退款等写操作仍由 `submit_after_sales_case` 完成，必须等待用户明确确认；自主循环不会调用它。
- `REQUEST_CUSTOMER_EVIDENCE` 只生成具体追问，不能从当前对话猜测或自动补造证据。
- `REQUIRES_HUMAN_CAPABILITY` 只记录 `UNSUPPORTED_CAPABILITY` 并停止；本轮不新增人工流程或视觉模型。
- 案件、裁决、政策版本与计划身份不一致时状态为 `STALE`，执行器不尝试修补或绕过。
- 同一 Run 内继续案件时使用动作级幂等键；工具提交后崩溃，恢复会复用 Tool Ledger 结果，不重复添加证据、裁决或计划。
- 已提交副作用和历史裁决永久保留。新证据只产生新的案件修订，不改写旧记录。
- 明确、确定性的售后路径不额外调用模型；证据语义核验仍只在对应政策要求需要时经过现有 Model Gateway。

## 可观测性

运行事件按顺序保存：

- `case_state_projected`：完整记录状态身份、案件版本、政策裁决、计划和义务；
- `case_obligation_verified`：记录指令、核验器版本、状态与原因码；
- `case_autonomous_action_selected`：记录准备提交的操作和参数；
- `case_autonomous_action_completed`：记录工具状态及案件版本进展；
- `case_execution_paused`：记录等待输入、等待确认、能力阻断、主动弃权或预算耗尽。

Run Inspector 把这些事件投影到执行主脊，并展示政策与计划身份、实际自主动作、版本进展和暂停边界。原始事件仍是权威证据，界面不根据结果反推或补造执行步骤。

## 验证边界

单元测试覆盖稳定状态身份、过期计划失败关闭、客户材料与明确确认边界、人工能力阻断，以及伪造自动动作拒绝。集成测试覆盖权威订单取证后进入确认、零语义模型调用、退款未提交，以及工具提交后崩溃恢复不重复取证。

这些测试证明机制按设计工作，不证明真实任务完成率已经提升。后续只有在冻结任务集上与基线进行可复查对照、保留失败样本并通过 Gate，才能宣称能力收益。V4 已在独立候选 Profile 中增加义务图、全候选过程核验和有界动作求解，详见《义务图主动证据获取设计》；V1–V3 仍保留本设计的固定优先级选择器。
