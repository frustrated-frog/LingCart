# 售后规划二版验证记录

## 本次改变

- 原文引用：模型返回 `source_ref`，宿主从 HUMAN 消息目录还原 `source_quote`，保存消息身份、字符范围和来源类型。ID 绑定当前 Run；跨 Run 的旧 ID、未知 ID 和助手文字均不能作为当前引用。每个片段最长 500 字，保留完整字符范围；最后四条用户历史可参与引用。
- 规划时机：只有相邻、同案件且显式依赖上一材料版本的更新才合批。仍逐项写账本并核验，最后再选下一动作。不是数据库事务合并；中途失败保留已完成部分，且不生成批次成功或提交确认。
- 决策对照：最新选择按案件保存到会话状态，下一轮展示上次运行、原选择、当前材料状态及本次判断。重放从冻结的上轮状态开始，避免把恢复途中保存的新决策误当作旧输入。
- UI 的预期信息仍标记为“尚未发生”。历史选择不是动作完成证据；材料操作数来自当前运行的真实工具结果。

v1 与 v2 只在 planning 槽不同，其他槽一致。v1 保留文本引用及每项材料后的规划路径；v2 保持 candidate，产品默认入口不变。

## 开发对照约定

固定源码 `a7948f5`，使用 `eval/after_sales_model_planning_v2_dev_tasks.json`，七个 dev 场景、每组每项重复两次。基线为 `after-sales-model-planning-v1`，候选为 `after-sales-model-planning-v2`。模型通过统一 Gateway 调用；每轮模型调用上限 8，每次 Provider 尝试上限 1。

场景：两种相反的首问顺序、同时补齐两类材料、延期后补交、补齐材料同时改为只保存案件、冲突陈述、多订单请求的范围澄清。后两项接受安全澄清，但不接受越权提交或退款；多订单项只检查明确拒绝一次确认覆盖多个案件，并未验证多案件协同执行能力。

完整通过要求既有逐轮断言、额外材料/顺序检查和预先声明的最终状态全部满足。没有使用 test split 调整提示词，也没有增加预算或修改本批数据以通过失败样本。

```bash
venv/bin/python research/experiments/after-sales-model-planning-v2/run_smoke.py \
  --output research/experiments/after-sales-model-planning-v2/run-next
```

## 真实模型结果

使用 `openai_compatible / deepseek-flash`，`run-01` 两组的源码树、数据和预算指纹一致。两组均实际运行 14 条多轮轨迹，没有按最好重复挑选。

| 指标 | v1 基线 | v2 候选 |
| --- | ---: | ---: |
| 开发场景完整验收 | 7/14 | 12/14 |
| 规划输出校验拒绝次数 | 7 | 0 |
| 规划模型调用 | 34 | 31 |
| 全部模型调用 | 138 | 140 |
| 总 Token | 487689 | 508135 |
| 每条多轮轨迹平均耗时 | 21.66 秒 | 28.06 秒 |
| 越权写入 / 重复动作 | 0 / 0 | 0 / 0 |

v1 的七次拒绝细分为三次原文引用不合法、四次 SELECT 携带问题字段。v2 本批均未发生；不能将全部七次拒绝都归因于引用问题。v2 中两种首问顺序、双材料补齐、延期后补交、冲突陈述和多订单澄清各通过 2/2。冲突和多订单项以符合预设的安全澄清为合格，并不意味着售后案件已解决。v2 三次成功引用历史 HUMAN 片段；引用次数不能直接视为收益。

双材料补齐的两次重复均观察到：v1 最后一轮规划两次，v2 规划一次，两组均保留两次材料写入。这支持合批减少中间规划的局部结论。但整批 v2 Token 增加约 4.2%、平均耗时增加约 29.6%，不能宣称整体成本或延迟下降；不同失败位置和完成工作量也会影响整批成本。

两组的“补齐材料同时改变目标为只保存、不提交”均为 0/2。重新核对原始轨迹后修正失败归因：v1 两次均停在入口 `MODEL_CLARIFICATION`；v2 一次已经保存两项材料，随后规划器因缺少草稿完成路径进入 `MODEL_GOAL_CLARIFICATION`，另一次才停在入口。这包含目标表示和入口解释两个问题。v1 的冲突场景另有两次 `MODEL_FORMAT_ERROR`；v2 本批通过，但没有单独消融或扩大样本，不能把该差异归因为稳定的冲突理解提升。

本候选同时包含引用目录、批量规划和历史对照，尚未做三个部分的独立消融。它仍为 candidate，正式 test 对照和晋升 Gate 尚未运行；现有模型调用次数不可回退的门槛没有放宽。

## 仍有边界

片段 ID 解决的是引用传输可靠性，无法证明模型引用的内容与选择在语义上相关，也不赋予权限。批量合并仅覆盖连续同案更新，独立动作仍需新观察后决策。历史选择是执行记忆，不是从成功失败中提炼的策略学习。本阶段尚未接入 ACE/PG 的售后学习，也未运行正式 test 对照或晋升候选。
