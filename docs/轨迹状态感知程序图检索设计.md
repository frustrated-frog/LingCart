# 轨迹状态感知程序图检索设计

## 问题与边界

PG v1 只用最近一次 `adaptive_decision` 的动作名作为图锚点。动作不在图中时，它把整张图作为回退上下文。真实冒烟中，Agent 在完成政策查询后仍有推荐目标未完成，最近动作 `answer_faq` 不属于购物程序图，于是定位器丢失此前的空检索状态并回退全图。

v2 只替换定位与局部检索变量。程序图、Refiner、指导 Prompt、Stable Kernel、工具协议、核验器和预算边界保持不变。它不增加一次模型调用，也不根据商品名称、品类或某一句用户问题堆叠规则。

## 轨迹状态

定位器从已经持久化的 Runtime、目标账本和计划生成 `TrajectoryState`：

- 目标是否建立、目标修订和约束绑定修订；
- 最近六个已提交动作及其事件序号；
- 对应步骤是成功、空结果、非空结果、错误还是待完成；
- 未完成目标的协议类型；
- 目标账本是否全部核验；
- 当前待执行步骤和机器可读反馈码。

状态投影不复制完整商品、订单或用户文本，不把模型工作记忆当事实，也不从自然语言猜测授权。用户修改目标后，只读取当前 `goal_revision` 的动作。

## 可解释定位

每个候选节点由若干独立信号累计得分：目标生命周期、最近已知动作、失败恢复、待执行步骤、未完成目标以及到未完成目标节点的图距离。事件中保留前八个候选、每项权重、最终置信度和选择原因。

以下约束是硬边界：

1. 图外的最近动作不会自动触发全图回退；
2. 只有仍能通向未完成目标，或对应步骤明确为空／错误时，较早的图内动作才可继续作为恢复锚点；
3. 得分不足时返回 `LOCALIZATION_ABSTAINED`，不调用指导模型；
4. 目标尚未建立时定位 `Start`，目标已建立但尚无行动时定位 `set_goal`，全部目标核验后定位 `complete`；
5. 定位器不执行工具、不改变预算、权限、确认或目标状态。

## 有界局部子图

检索从唯一锚点沿有向边执行最多三跳 BFS，默认两跳、最多六条边。相同深度内优先保留目标节点得分更高的关系，并记录被预算裁剪的边编号。模型只能引用这次检索实际提供的边；不存在锚点或没有后继关系时不会调用指导模型。

v1 定位器仍以影子模式对同一状态计算结果。影子只用于记录锚点差异、全图回退和候选范围，不进入 Prompt，也不改变模型、工具或核验路径，因此不会把对照本身变成第二个干预变量。

## 证据与指标

每次 `pg_guidance` 事件新增：

- `localization.algorithm/status/reason/confidence`；
- 候选节点和分项得分；
- 裁剪关系编号；
- v1 影子锚点、边范围及是否全图回退；
- `abstained` 与原有 `fallback` 的明确区分。

实验投影额外统计定位弃权、影子差异和影子全图回退。`LOCALIZATION_ABSTAINED` 表示证据不足时主动不干预，不与指导模型失败或上下文预算不足混为一类。

## 评测纪律

`eval/pg_localization_tasks.json` 是零模型调用的机制契约，只验证状态定位和子图边界，不是业务效果或论文收益证据。固定 Gate 要求全部锚点与必要关系命中、候选不超过边预算、全图回退为零。

PG13 的真实失败已经参与 v2 的问题选择，因此它从本轮起只能作为回归诊断，不再是能支持无偏收益声明的“未见测试”。v2 保持 `candidate`；完整实验即使执行，也只能验证工程稳定性。正式收益结论需要在实现冻结后另建未参与设计的新 holdout，并同时比较成功率、恢复率、无效调用、模型尝试和 Token。
