# 证据驱动售后规划 V1

## 不变量与边界

- 证据内容不可变；来源核验只证明材料来自何处，不证明用户陈述属实。政策必须显式声明接受来源和充分性条件，不能仅按类型存在判定满足。
- 证据添加、撤回、替换、验证、政策重算和计划修订使用同一案件版本与本地事务；Tool Ledger 继续负责恢复和重放。旧事件、裁决、已执行退款永久保留。
- Case 是跨 Run 业务身份。只能在当前持久会话内引用案件；多个候选时澄清，不按最近一次猜测。模型只能选择政策公开的要求，不能提交验证状态、可信来源或授权。
- 证据依赖改变即关闭旧授权；提交仍重新核对案件版本、政策指纹、权威事实与证据有效期。补证永远不等于同意退款。
- CasePlan 是版本化的业务目标及依赖投影，不创建第二个 Runtime。执行仍经 Capability Registry、TaskPlan、ToolExecutor 与 Checkpoint；已有 LivePlan 可观察同一执行轨迹。
- 已提交或终止案件禁止证据变更，重规划不能回放已提交副作用。
- 旧数据库仅增加表；旧证据缺少验证记录时视为未验证。旧政策与裁决内容保留，新增政策版本显式定义证据接受规则。

## 交付范围

先支持当前用户原文与权威订单记录。政策返回结构化 EvidenceRequirement，记录政策身份、目标、来源条件、验证条件、状态及引用。案件计划持久记录未满足要求、合法动作及相邻版本差异；材料变化后仅重新计算受影响的要求，政策和退款前置事实仍完整核验。

新增跨轮继续案件能力：重读案件、提交某项要求的文本材料、撤回证据、替换旧材料。来源由服务器生成并从持久 Run 核验，所有写入通过既有事务工具边界。图片/OCR、人工裁决队列、外部退款处理暂不实现，也不声称 LLM-Modulo 研究收益；本轮交付的是可评测的生产基础机制。
