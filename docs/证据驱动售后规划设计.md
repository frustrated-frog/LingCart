# 证据驱动售后规划 V1

## 不变量与边界

- 证据内容不可变；来源核验只证明材料来自何处，不证明用户陈述属实。政策必须显式声明接受来源和充分性条件，不能仅按类型存在判定满足。
- 证据添加、撤回、替换、验证、政策重算和计划修订使用同一案件版本与本地事务；Tool Ledger 继续负责恢复和重放。旧事件、裁决、已执行退款永久保留。
- Case 是跨 Run 业务身份。只能在当前持久会话内引用案件；多个候选时澄清，不按最近一次猜测。模型只能选择政策公开的要求，不能提交验证状态、可信来源或授权。
- 证据依赖改变即关闭旧授权；提交仍重新核对案件版本、政策指纹、权威事实与证据有效期。补证永远不等于同意退款。
- CasePlan 是版本化的业务目标及依赖投影，不创建第二个 Runtime。执行仍经 Capability Registry、TaskPlan、ToolExecutor 与 Checkpoint；已有 LivePlan 可观察同一执行轨迹。
- 已提交或终止案件禁止证据变更，重规划不能回放已提交副作用。
- 旧数据库仅增加表；旧证据缺少验证记录时视为未验证。旧政策与裁决内容保留，新增政策版本显式定义证据接受规则。

## 交付范围

先支持当前用户原文与权威订单记录。政策返回结构化 EvidenceRequirement，记录政策身份、目标、来源条件、验证条件、状态及引用。材料变化后完整核验政策和权威事实，比较目标依赖指纹，保留未受影响的目标，只修订发生变化的目标。当前采用确定性的依赖差异比较，没有宣称计算量下降。

新增跨轮继续案件能力：重读案件、提交某项要求的文本材料、撤回证据、替换旧材料。来源由服务器生成并从持久 Run 核验，所有写入通过既有事务工具边界。图片/OCR、人工裁决队列、外部退款处理暂不实现，也不声称 LLM-Modulo 研究收益；本轮交付的是可评测的生产基础机制。

## 实现与恢复

- `AFTER_SALES_CONTINUE` 从当前会话账本解析 Case，模型选择政策要求并引用本轮原文。案件不唯一时返回澄清。实际工具再次核对会话、案件版本、要求及原文，禁止模型传入验证结论或伪造来源。
- 同一 Run 的案件上下文冻结到 Checkpoint，避免工具已提交但事件尚未保存时，恢复产生不同 Prompt。Tool Ledger 重放原结果，不重复新增材料、裁决或计划。
- `after_sales_evidence_validations` 保存来源核验身份、材料指纹和案件版本；旧证据没有该记录时保持未验证。政策的 `evidence_acceptance` 决定允许的来源、验证条件及有效期。
- `after_sales_case_plans` 保存每次裁决的目标依赖、行动、前驱版本及差异。重复评估同样的输入复用原裁决及计划。退款提交后新增已提交计划，保留历史审批与证据。
- 补证/撤回事务关闭旧 `PendingAction`，最终保存 Run 时也拒绝恢复已经关闭的授权。新授权绑定新的案件版本和裁决，提交前仍重新评估全部政策输入。
- 查询投影按当前政策、日期及业务事实检测陈旧裁决，旧结论及计划显示失效，不修改历史账本。原始依赖保留供审计。

## 演示政策升级

默认演示政策从 `2026-01` 升级为 `2026-02`，明确允许已核验来源的用户陈述满足声明类要求，不把陈述解释为独立鉴定。只有指纹仍匹配原始种子规则的旧政策会被标记为 `RETIRED`，原规则与历史裁决不改写。定制政策如与新版本同时有效，既有重叠检测会拒绝猜测，需要管理员明确适用版本。

## 验证范围与后续工作

离线测试覆盖来源伪造、跨会话、证据过期、权威记录变化、撤回与旧授权关闭、并发版本冲突、工具提交后崩溃恢复、双要求增量修订、相同输入复用以及旧政策兼容。桌面页面从测试 SQLite/Runtime/API 链路读取材料与计划，不在生产组件中注入假数据。

这轮自然语言测试采用脚本模型，尚无真实模型泛化结论。当前处理用户明确撤回/替换和权威来源变化；任意两段自然语言陈述之间的自动矛盾裁决、附件鉴定及人工审核执行仍需后续能力。候选论文机制的 baseline/candidate 对照与真实模型评测需单独冻结实验契约后开展。
