# 失败恢复专项评测与演化对比页

## 本阶段目标与不变量

在既有 RRSI 单模块演化之上，补齐可解释的恢复反馈、专用故障任务和只读对比页。不改变生产默认 Profile、权限、用户确认或工具账本；不为实验提高某一候选的任务预算。学习只使用 dev 摘要；test 只在冻结后运行。所有负结果保留。

## 任务与反馈

`eval/rrsi_recovery_tasks.json` 包含 18 个消费任务，train / validation / test 各六题，均覆盖超时、空结果、参数拒绝、价格变化、连续工具失败和运行中目标修改。每组使用不同品类和预算。它是人工构造的域内故障任务集，不是外部泛化基准。

超时使用可审计的 `TOOL_TIMEOUT` 故障注入，不靠真实等待耗尽时间。连续失败注入四次，包含工具执行器自身的有界读取重试；参数拒绝发生在既有参数校验边界。故障仅存在于 eval 上下文，退出时恢复原函数。各类故障必须实际触发，否则原评测器判失败。价格与目标变化沿用已有注入和核验流程。

`recovery_trace` 根据完成步骤与事件序号定位空结果、失败和决策拒绝，再关联后续最多三步：是否重复工具及参数、新增商品记录数量（不覆盖其他类型的信息增益）、原始任务是否通过、最终已核验目标数。计算新观察时只输出数量，不向学习器提供具体商品、订单、查询参数和答案。

必须区分：获得新观察、最终任务通过、修改导致成功。这三者不等价。摘要只提供前两类可观测事实，不声称因果归因。`repeated_without_new_records` 是失败窗口中的重复链接数量，多个窗口可覆盖同一步，不是全 Run 的去重重试计数。同任务既有成功重复又有失败重复时，输出 sample_ref 对照；没有配对时保持空列表。

训练摘要独立保存为 `round-N-feedback.json`，不只存在于提示词里。

## 四组留出对照

使用 `--ablation` 替代 `--heldout`，两者不能同时启用。演化完成后冻结如下四组：

| 组 | 机制 |
| --- | --- |
| baseline | 原始 adaptive-v1，无新增规划/恢复模块 |
| fixed | 初始固定程序 |
| schedule_control | 使用候选的触发时机与 inline/deliberate，但恢复为 seed 指令 |
| evolved | 最终保留程序 |

总模型调用、Token 与时间上限一致。调用策略对照帮助分析额外分析是否解释结果，但状态变化仍可能导致实际调用次数不同，因此不是完全控制计算量的因果实验。演化策略必须对三组均不退化并满足成本门槛，且确有程序变化，才报告观察到改善；永不自动晋升。

正式 spec 每组六题、三次重复、两轮；smoke 每组一题、两次重复、一轮。正式实验较昂贵，smoke 的多次重复仍不足以证明跨故障类型泛化。

```bash
# 无模型调用的配置校验
venv/bin/python -m eval.run_rrsi_eval --spec research/experiments/rrsi-recovery-v2/evolution-spec.json

# 显式真实模型，14 个任务运行上限（候选被提前拒绝时更少）
venv/bin/python -m eval.run_rrsi_eval --live --ablation \
  --spec research/experiments/rrsi-recovery-v2/smoke-spec.json \
  --output-dir research/rrsi/recovery-v2-smoke-01
```

## 只读演化对比页

入口：论文实验室 → 规划与恢复 · 自进化对比，地址 `/experiments/rsi`。API 为 `/engineering/rrsi/runs` 和 `/engineering/rrsi/runs/{run_id}`，继承工程访问控制。

从 `research/rrsi/` 的实际产物投影版本、候选、程序字段差异、同 case / repetition 的父子验证轨迹和留出结果。父版本依据产物指纹寻找报告，不默认把所有候选都与 seed 对比。空态、读取错误、部分产物和历史源码提交单独呈现。页面不提供付费实验启动按钮，实验仍由明确的 CLI 入口启动。

API 拒绝路径逃逸和符号链接，并对读取大小设上限。没有模型调用或业务写操作。UI 不读取本地 JSON、不模拟运行状态、不把缺少的轨迹显示为零成功率。候选在 Critic 或协议阶段被拒绝时，右侧明确显示没有执行轨迹。

对照表依据冻结合同中的程序指纹标注使用同一程序的组别，防止把随机波动归因于策略演化。本轮真实结果与验证范围见[失败恢复专项验证记录](失败恢复专项验证记录.md)。
