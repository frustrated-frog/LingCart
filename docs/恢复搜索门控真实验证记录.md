## 用量完整性修复

实测暴露了原回放统计的缺陷：Runtime 的 usage 只汇总已有响应用量，后续模型失败时，它仍可能是正数。旧回放会把这个部分值误当作全量成本，尤其是“先成功调用、再余额不足”的样本。

后续代码用 `model_started` / `model_retry`、成功响应条数、provider 用量和后续模型调用计数交叉检查；任何调用缺失用量，总成本均为未知，预算中的保守估算不填入实际用量。页面同时显示已知部分。该修复已覆盖离线回归，不再发送真实模型请求。

原始 `summary.json` 保持不变，其中按需组 `suffix_tokens=83556` 包含上述部分值，**不可作为完整组成本使用**。新增 `usage-audit.json` 保存原合同/摘要指纹、审计代码指纹及派生结果，三组完整总成本均修正为未知。工程 API 对历史样本也从逐调用事件重新投影，不回写原产物。
