# 多轮理解与恢复二版设计

## 不变量

- 两阶段独立候选：第一阶段仅改变原文引用协议；第二阶段在第一阶段之上改变控制意图解释。各自固定基线、数据和预算，不混淆收益归因。
- 原文目录由宿主从本轮 HUMAN 构造，绑定 Run、消息和字符范围。模型选择 ID，不能修改文字、跨 Run 引用或用助手回答补造材料。持久化仍使用已有原文协议。
- 材料归属、政策充分性和授权仍分别核验。一个片段可以支持多项独立事实，但不能因此认定所有材料充分。
- 尚未授权是默认等待确认；明确禁止是持续约束。恢复目标不自动解除禁止、确认语义不自动授权工具。
- 暂停、撤回授权、恢复的效果通过已有工具执行、检查点和确认账本实现；不增加第二套执行器。
- UI 展示原文定位和解释结果，不把模型提议或来源定位当成材料已入账。
- 不增加模型调用次数上限、重试次数或上下文预算。既有 Profile 与原始负结果保留。

## 实现与实验

`after-sales-source-refs-v1` 仅替换 tool protocol：模型在宿主生成的本轮原文目录里选择 ID，宿主恢复完整原文，分别交给材料归属与独立需求核验。旧契约的模型输入省去重复来源范围、哈希和修订元数据，原始契约仍保存在账本并参与指纹校验。

`after-sales-control-intent-v1` 在上述候选之上仅替换 planning：解释等待确认、明确禁止、解除指定禁止与撤回旧授权。控制意图与独立需求提取必须匹配。明确禁止可先收窄权限；放宽限制必须等整份理解通过校验。案件身份从会话账本绑定，不通过关键词替代语义解释。

Stable Kernel 持久化范围限制和撤回的确认身份；在旧确认展示、工具 preflight 与副作用执行前检查。范围为 CASE 或 SESSION，解除某案件禁令不影响其他范围，普通恢复也不能解除旧的全局禁令。撤回当轮不重发确认，后续继续处理可重新核验并取得新确认。

Run Inspector 展示原文片段、控制解释、作用范围与历史解释选择；材料是否入账仍以工具结果为准。没有新事件时展示空态，不推断控制结果。

## 冻结验证

两个实验分别位于 `research/experiments/after-sales-source-refs-v1` 与 `research/experiments/after-sales-control-intent-v1`。共同数据 `eval/after_sales_understanding_tasks.json` 包含既有 5 项 dev 诊断与 3 项新的 test 表达变体；各重复两次。test 不参与后续调参。三组使用同一源码、模型配置、预算与数据，逐样本保存原始轨迹；不会挑选最佳重复。

运行命令：`venv/bin/python eval/run_case_understanding_eval.py --live --split dev --output-dir <empty-directory>`；正式表达变体使用 `--split test`。没有 `--live` 只校验数据。每个 Run 最多 8 次模型调用，每次 Provider 最多尝试 1 次，继承既有 16000 字符上下文、45 秒和 Token 预算。额外判定检查本轮实际入账材料与恢复后的新确认身份。

成本门槛保留“模型调用不增加”，不因为成功率提升而自动放宽。评测报告不触发晋升，产品入口仍拒绝这两个候选。
