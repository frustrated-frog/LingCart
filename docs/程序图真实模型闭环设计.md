# 程序图真实模型闭环设计

## 目标

本轮不扩展新的论文机制，只验证 Procedural Graph（PG）能否在真实模型路径中形成以下闭环：

`训练轨迹 → Refiner → GraphPatch → 验证选择 → 冻结图 → 在线指导 → Agent 决策 → 工具结果 → 目标核验`

完成工程闭环不等于证明 PG 有收益。冒烟结果只能说明链路是否真实贯通，正式结论必须来自冻结版本后的重复测试对照。

## 三组对照

- `baseline`：原始 Adaptive Agent，不注入 PG。
- `seed`：绑定种子程序图，只验证固定图指导的影响。
- `evolved`：绑定训练与验证后保留的图，验证演化是否带来额外变化。

三组必须使用相同数据身份、源码身份、模型配置、运行预算和隔离业务初态。训练与验证只能读取 `dev` 案例；测试案例在图和实验契约冻结后才运行，Refiner 永远不能读取测试轨迹。

## 低成本冒烟协议

冒烟只选择同一能力主题的三个不同情境族：

- 训练：`PG01`；
- 验证：`PG07`；
- 测试：`PG13`。

一次冒烟包含种子图验证、一次训练、一次候选验证，以及无 PG／种子图／演化图各一个测试样本，共最多 6 个样本。硬限制为：

- 每个 Run 最多 8 次模型尝试；
- 每次逻辑模型调用不做 Provider 重试；
- Refiner 最多 2 个 Runtime 模型调用额度，当前实现只发起一次逻辑调用；
- 单 Run 最多 48,000 prompt token unit、2,000 completion token unit；
- Refiner 最多 60,000 prompt token unit、1,500 completion token unit；
- 全任务最多 50 次模型尝试、361,500 token unit。

`token unit` 优先采用 Provider usage；Provider 不返回 usage 时使用 Runtime 的保守 UTF-8 预留值，不能把未知消耗记成零。任何预算超限都会终止任务并保留已完成样本。完整实验仍保持冻结的 6/6/6 数据和三次重复，但 API 与 UI 要求用户再次明确确认高调用预算。

## 干预证据链

每次 PG 指导都持久化以下证据：

1. 当前目标修订、目标结构、反馈、最近行动与未完成步骤；
2. 定位锚点、是否回退全图、局部节点和候选关系；
3. 指导器选择的关系、指导内容、弃权或失败原因；
4. 指导是否真实进入 Agent 决策上下文；
5. 后续已提交的 Adaptive 决策；
6. 实际工具参数、受限结果摘要和独立核验事件。

样本完成后，系统从原始事件生成不可变 `pg_evidence` 投影并随样本一起落盘。原始事件仍是权威证据；投影只负责关联和展示，不生成隐藏推理，也不把“行动与边目标一致”夸大为模型因果解释。

## 失败分类

当前投影使用可由事件证明的阶段分类：

- `BASELINE_TASK_FAILURE`：无 PG 对照任务失败；
- `LOCALIZATION_ABSTAINED`：轨迹证据不足，v2 定位器主动不干预；
- `LOCALIZATION_FALLBACK`：定位器因未知锚点回退全图；
- `GUIDANCE_UNAVAILABLE`：指导失败、跳过或弃权；
- `GUIDANCE_NOT_EXPOSED`：生成了指导但未进入决策上下文；
- `NO_FOLLOWUP_DECISION`：暴露后没有已提交行动；
- `TOOL_OUTCOME_FAILURE`：后续工具返回错误或无效结果；
- `GUIDANCE_ACTION_DIVERGENCE`：指导关系直接指向行动节点，但实际行动不同；
- `GOAL_VERIFICATION_FAILURE`：行动完成后仍未通过目标核验；
- `UNCLASSIFIED_TASK_FAILURE`：现有证据不足以进一步归因。

只有关系目标本身是 `ACTION` 节点时，系统才判断 `ALIGNED` 或 `DIVERGED`。指向状态或推理节点的关系标记为 `UNKNOWN`，避免伪造“模型采纳了指导”的结论。

## 后续算法选择原则

真实冒烟完成后，先按失败阶段统计主导问题，再一次只改变一个算法变量：

- 定位回退或取错子图占主导：改进轨迹状态感知的 Localizer／Retriever；
- 指导已暴露但行动长期分歧：检查指导表达和决策协议；
- 行动对齐但工具或核验失败：优先修复执行、观察或 Verifier，不应继续修改图检索；
- 候选图在验证集退化：保留负结果，冻结 Refiner 其他变量后分析 GraphPatch。

冒烟不进行机制晋级，不声明成功率提升，也不使用测试集调参。

## 2026-10-24 首轮真实冒烟记录

首轮 smoke 使用 `openai_compatible / deepseek-flash`，共完成 5 个样本，消耗 27 次模型尝试和 72,870 token unit，未触及预算上限。候选验证没有执行，因为 Refiner 产出的 GraphPatch 在结构校验前被安全文本校验拒绝；因此测试阶段的 `evolved` 与 `seed` 实际绑定同一个图指纹。

三组测试均未成功，不能宣称 PG 有收益。种子图样本真实暴露了指导并改变了行动轨迹，但相比无 PG 基线增加了工具调用和模型成本。由于 smoke 只有一次重复，而且两个相同图版本的测试轨迹也出现了不同路径，这些差异只能作为后续定位线索，不能视为稳定效果。

Refiner 提案的常见错误字段包含“不得放宽预算等硬约束”。旧校验器把否定式安全要求误判为放宽约束，导致合理候选无法进入验证。现已修正为只豁免紧邻危险动作的明确否定表达，同时继续拒绝“建议放宽预算”“可以绕过审批”等实际弱化边界的内容。本次结果保留为历史负证据，不覆盖、不重跑，也不据此修改测试集。

修复后的第二轮 smoke（任务 `pg-8a23a199fb32480fb8526556a7794a95`）完整执行了 6 个样本，共 34 次模型尝试、87,599 token unit。Refiner 新增 `refine_query` 推理节点及空结果后的改写、重试与最小澄清关系；候选图在验证集上以成功率不退化且模型尝试从 8 次降至 3 次被保留，图指纹为 `89e674186a063edfa4f816ae4b4d724401bc51b1d0404ed41116dd2c2c8a06e6`。

最终测试的 baseline、seed、evolved 均未完成 `PG13`，成功率都为 0。baseline 使用 2 次模型尝试和 1 次工具调用；seed 使用 6 次模型尝试和 2 次工具调用；evolved 使用 7 次模型尝试和 4 次工具调用。两个 PG 组均真实暴露指导，但工具成本退化，因此实验门禁拒绝 seed 与 evolved，机制继续保持 `candidate`。证据投影将 seed 的主要失败归为 `NO_FOLLOWUP_DECISION`，将 evolved 归为 `LOCALIZATION_FALLBACK`。这表明下一轮应优先研究轨迹状态感知的节点定位与局部子图检索，并冻结 Refiner、模型与任务，不应把候选图已经保留误写成“效果提升”。

该定位改进已在 `adaptive-pg-context-v2` 中实现，设计见《轨迹状态感知程序图检索设计》。因为 PG13 的失败已经参与算法变量选择，从 v2 起它只作为回归诊断，不再支持未见测试收益声明。
