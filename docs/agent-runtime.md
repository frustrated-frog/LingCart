# Agent Core V1 运行与恢复

API 与 Streamlit 使用 `src.durable.run_conversation`，离线测试可直接调用无持久化的 `run_orchestrator`。现有 SQLite 文件首次启动时增建会话、消息、任务、步骤、工具账本、检查点和待确认操作表；支付及退款每订单唯一。若历史文件已有重复业务记录，迁移报错，需人工核对后处理，不自动删除。

## 会话与请求

`POST /chat` 接受 `message`、可选 `session_id`、`request_id`、`action_id`。客户端重试同一需求应重复使用 `request_id`：已结束的任务返回原结果，回复不重复入库。同一编号换需求返回冲突。客户端不传编号时每次请求均为新任务。

`GET /conversations/{session_id}` 返回已保存消息、业务上下文及 `active_run_id`。`GET /runs/{run_id}?session_id=...` 返回运行、检查点和事件。中断后调用 `POST /runs/{run_id}/resume`，请求体为 `{"session_id":"..."}`。运行中的租约不可抢占；进程退出后等待租约过期即可恢复，捕获到的中断立即释放租约。会话有未结束任务时拒绝开始新任务。会话 ID 是此本地演示的访问凭证，没有接入客户账户认证。

确认只针对服务端保存的当前待确认操作。客户端应回传展示的 `action_id`，过期操作返回冲突。审批绑定订单、金额和确认任务。缺支付方式时保留待确认操作。SQLite 的 `BEGIN IMMEDIATE` 将本地业务变更、工具账本及操作完成状态一起提交：事务内崩溃全部回滚，提交后崩溃复用账本结果。

## 有界执行

默认限制：8 次模型请求、12 次实际工具调用、16000 输入 token、3000 输出 token、30 秒、单次调用 10 秒、8 个计划步骤、依赖深度 4、只读工具至多尝试 2 次。限制由服务端设置，恢复沿用原限制和已消费预算。提供方轮换也计入模型尝试次数。预算冲突按时间、模型轮次、工具次数、输入 token、输出 token 的顺序停止。

提供方返回 token 用量时记录实际值；没有用量时显示未知，并用 UTF-8 字节数的保守估计预留预算。估计不代表账单 token，成本没有价格依据时保持未知。最后一个模型轮次解除工具绑定；仍返回工具请求会明确失败，不执行。工具白名单、严格参数、业务规则、服务端审批均在统一执行器检查。

只读工具和模型使用线程期限，超时线程无法被强杀，工作线程总数限制为 8。本地数据库写事务必须同步结束，不会在提交过程中强行取消；最终提交可能略晚于运行时限。未来外部写入不具有 SQLite 原子保证，超时或执行中断记录为结果不确定，禁止自动重放。读模型的失败仅在调用边界有限重试，不重试整个业务流程。

## 恢复日志

恢复从保存的输入、模型决策、预算和工具账本重新构建执行前缀，成功的模型与工具结果直接复用，新的步骤继续追加事件。所有事件携带同一 `run_id` 和递增序号；复用明确标记。最终结果、会话状态与唯一助手回复一次性入库。读结果可能是该运行早先观察到的状态，重新核验当前状态需创建新请求。
