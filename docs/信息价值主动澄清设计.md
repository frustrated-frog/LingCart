# 信息价值主动澄清设计

## 1. 目标与研究边界

V4 已把当前政策要求和所有持久化行动编译成 `ObligationGraph`，能够先走可信权威工具，再在补证、等待、审批和能力边界之间确定性选择。V5 继续解决一个更窄的问题：存在多个合法用户问题时，应该先问哪一个。

`after-sales-active-clarification-v5@5.1.0` 借鉴 ICML 2026 论文 *Uncertainty-Aware Clarification in LLM Agents with Information Gain*（`PMLR:v306:deng26l`）的信息增益驱动主动澄清思想，但不是论文训练方法的复现。当前系统没有经过校准的用户回答概率，也没有足够实验支持真实熵估计，因此只计算可解释的结构上界，不能把它称为期望成功率或实验收益。

本阶段保持以下边界：

- 不由 Planner 自由生成新问题，只消费政策裁决和独立语义核验中已经持久化的问题；
- 可信、无需授权的权威工具动作继续优先于询问用户；
- 有有效延期声明的义务不进入问题组合，避免重复追问；
- 一次只选择一个政策义务的问题，不把多个义务拼成一次写入；
- 退款提交仍必须经过用户明确确认和 Stable Kernel；
- V5 仍是 research-only candidate，产品入口不能直接选择。

单义务限制不是产品妥协，而是当前写入协议的真实约束：同轮多个 `AFTER_SALES_CONTINUE` 会共享读取时的案件修订号，第一个写入后，第二个必须重新读取或进入事务性批处理。V5 不通过批量提问提前制造无法安全消费的回答；这个问题留给后续多义务协调机制。

## 2. 澄清组合

每次 V5 求解在 `ObligationGraph` 之后构建 `ClarificationPortfolio`。只有图中已通过全候选校验的 `ASK_USER` 动作才能成为问题候选。

每个 `ClarificationQuestionCandidate` 绑定：

- `obligation_candidate_id` 与唯一 `requirement_id`；
- 已持久化的精确问题文本；
- 当前政策裁决中的语义核验身份和完整内容指纹；
- `missing_information` 编译出的原子未知条件；
- 回答分支、信息消除上界、政策解锁上界、交互轮次和回答负担；
- 稳定 `question_id`。

当独立语义核验给出有效的 `missing_information` 时，只有被问题文本明确覆盖的缺口才形成 `SEMANTIC_GAP` 并进入信息上界。其余报告缺口只保留数量用于审计，不能让模型通过罗列额外缺口提高排序。模型不可用、协议降级、尚无核验或问题没有明确覆盖缺口时，只使用政策要求描述形成一个 `POLICY_REQUIREMENT`，不会因为错误输出虚增信息价值。

语义核验协议最多允许八个缺口；超过上限、字段类型异常或持久化要求集合损坏时，组合返回机器可读的 `INVALID`，需要提问的路径失败关闭，而不是在 Planner 中抛出未分类异常。

问题必须与当前政策要求、案件状态和 CasePlan 中的问题逐字一致。身份失配、重复要求、异常字段或不完整问题集合都会形成机器可读校验问题；真正需要提问时，组合无效会失败关闭。

## 3. 反事实答案分支

V5 为每个问题枚举四类结构化后继，而不预测用户会落入哪一类：

1. `SUFFICIENT_EVIDENCE`：独立语义核验可能确认材料充分，并解锁对应义务；
2. `PARTIAL_EVIDENCE`：可能消除部分未知条件，但义务仍需重新核验；
3. `EXPLICIT_DEFERRAL`：形成受信任 Readiness 后转为等待，不把延期当证据；
4. `UNRESOLVED_OR_CONFLICT`：回答仍未知、矛盾或不相关，需要后续纠正。

分支中的数值全部是上界。例如 `resolves_unknown_upper_bound=2` 只表示该问题覆盖两个已记录缺口，不表示用户一定回答、回答一定真实或政策一定通过。所有实际状态变化仍由下一轮来源核验、语义核验、Policy Engine 和案件修订完成。

## 4. Pareto 前沿与确定性选择

问题之间先按以下维度计算支配关系：

- 政策解锁上界越大越好；
- 可消除未知条件越多越好；
- 语义缺口越具体越好；
- 回答负担和交互轮次越小越好。

如果一个问题在全部维度不差、且至少一个维度更好，它支配另一个问题。求解器只在非支配问题的 Pareto 前沿中选择，随后使用稳定序列打破平局：政策解锁、未知消除、语义具体性、回答负担和要求身份。

这里保留两层选择证据：

- `ActiveClarificationDecision` 解释问题前沿、被支配问题和最终问题；
- `CandidateSelection` 把最终问题重新绑定到完整义务图候选集合，确保没有绕过自动工具、等待、审批或能力边界。

任何被篡改、遗漏候选或指纹不一致的 Selection 都会以 `OBLIGATION_SELECTION_INVALID` 失败关闭。

## 5. 执行、恢复与可观测性

执行链为：

```text
CaseExecutionState
  -> ObligationGraph 全候选核验
  -> ClarificationPortfolio 编译
  -> 可信非用户动作优先 / Pareto 问题选择
  -> ObligationActionDirective
  -> ToolExecutor 或持久化等待边界
```

每轮新增 `case_clarification_portfolio_solved` 事件，保存完整组合、反事实分支、求解身份和最终选择。`autonomous_execution` 保存全部 portfolio/decision ID、最终问题 ID 和问题文本。5.1 还会把最终问题持久化成独立的 Pending Clarification，绑定案件修订、政策版本与指纹、要求、问题内容指纹和求解身份；它与用于支付、退款授权的 `PendingAction` 完全分离。

下一轮回答只由运行时从当前有效问题账本绑定，模型看不到内部 `clarification_id`，也不能自行提供该编号。回答写入与问题消费在 ToolExecutor 的同一事务完成，之后仍必须经过独立语义核验、Policy Engine 和义务图重建。工具事务已经提交但进程随后崩溃时，Tool Ledger 会复用同一结果，不重复添加证据或重复消费问题。对应审计事件为 `case_clarification_opened` 与 `case_clarification_answer_bound`。

Run Inspector 展示问题数量、选择原因和最终问题。面向用户的售后回复只呈现被选中的问题，不再把所有缺失项无差别拼接输出。React 对文本做普通转义，问题仍被视为不可信数据。

## 6. 当前限制与下一步

- 当前信息价值是结构上界，没有概率、熵或学习到的 Reward；
- 一个持久化问题只覆盖一个政策义务；跨轮回答已经可以安全绑定，但还不能安全消费同轮多义务回答；
- 语义缺口来自独立核验模型，但只影响提问排序，不能满足政策、授予权限或授权退款；
- 尚未运行真实模型对照，不能宣称减少了平均提问次数或提高成功率。

下一阶段应实现多义务协调：把一次用户输入拆成多个来源绑定更新，通过受控顺序重读或事务性批处理解决案件修订冲突，并在每次写入后重新构建义务图。真实模型评测仍按当前安排暂缓；恢复时继续使用冻结任务集验证问题数量、无效追问、任务成功率和额外成本。
