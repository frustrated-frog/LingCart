# 共享失败身份与有界恢复

## 目的与边界

将模型协议、工具参数、独立审查、执行反馈和推荐核验的重复失败纳入同一个宿主维护的账本。它只决定是否继续尝试同类失败，不授权工具、不扩大预算、不修改已接受的目标、确认条件或实验配置。

## 身份与持久化

`FailureSignature` 的版本为 `failure-signature/v1`，由阶段、错误码、目标摘要和执行依据摘要构成。依据包含请求、目标修订、目标内容和约束映射；推荐失败还绑定最新目录读取中的对应商品事实。相同商品事实的重复查询、不同步骤号、时间戳不算进展。失败签名不包含原始模型响应或工具参数明文。

账本保存在 Runtime 检查点的 `failure_ledger`，并和 `failure_registered` 事件一起写入现有持久化边界。每次失败绑定模型调用游标或选择步骤，恢复重放同一次响应不重复计数。每次运行最多 64 个失败身份，不能无界增长。

默认每个身份最多恢复两次；推荐核验沿用最多两次实际失败的限制。达到限制只禁止继续相同失败，不禁止用户修订目标、获取改变后的事实或更换候选。全局模型、工具、时间、步骤和既有决策修复预算仍有效。旧 `selection_failures` 仅供旧检查点兼容，新记录写入共享账本。

## 恢复动作

宿主返回 `REPAIR_PROTOCOL`、`REPAIR_ARGUMENTS`、`REVISE_INTERPRETATION`、`REVISE_BINDING`、`CHANGE_CANDIDATE_OR_EVIDENCE` 或 `STOP`。模型仍负责提出修正方案，原有类型、来源、语义审查与 ToolExecutor 才能批准执行。

普通对话的既有一次协议修复也记录到共享账本；原有未知能力降级、必要澄清行为不变。它不是自动选择所有业务恢复步骤的通用规划器。

模型上下文只接收恢复动作和次数，完整指纹保留在工程记录中；预算紧张时辅助恢复提示不能挤出最新完整事实。运行检查页展示真实失败次数、恢复动作和身份指纹，历史运行没有记录时展示空态。

## 验证

- 同一失败的持久化、重复注册幂等、达到上限停止、改变目标/事实后重新尝试。
- SQLite 检查点在第二次参数失败后崩溃，恢复复用缓存响应不重复计数；第三次失败终止，非法工具调用从未执行。
- 独立审查连续畸形协议提前停止，不降级为批准。
- 页面测试覆盖真实协议投影的计数、停止状态和空态。
