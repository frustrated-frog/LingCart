# 消费工作台视觉系统设计

## 目标

第一阶段只重构设计基础和消费工作台，不在同一次改动中重写论文实验室与售后领域模型。页面的唯一核心任务是：让用户清楚表达消费目标，并在同一视图中看到真实执行状态、结果和证据。

## 视觉方向

LingCart 使用“任务收据 + 执行路线”的视觉语言，而不是通用后台仪表盘。收据代表商品、订单与可核验事实；路线代表 Agent 从需求理解到结果交付的真实执行链。

### 色彩

- `porcelain` `#F3F4EF`：应用画布，减少纯白页面的眩光。
- `paper` `#FCFDFB`：主要工作面与消息承载面。
- `forest_ink` `#17231D`：正文和主导航，表达稳定与可信。
- `evidence_green` `#19735C`：已核验、已同步和安全状态。
- `signal_blue` `#4059C7`：主要操作、当前步骤和可交互状态。
- `warm_signal` `#D97745`：审批、等待与需要用户介入的状态。

错误、警告和研究候选色继续使用现有语义变量，不以装饰色覆盖业务状态。

### 排版

- 中文标题：`Avenir Next` / `PingFang SC`，更大的字号与更紧的字距。
- 正文：`Inter` / `PingFang SC`，默认正文不低于 13px。
- 证据与标识：`IBM Plex Mono` / `SFMono-Regular`，只用于 ID、事件和机器字段。

### 布局

```text
┌──────────────┬──────────────────────────────────────────────┐
│ 产品与研发导航 │ 任务标题 / 可信边界                         │
│              ├───────────────────────────────┬──────────────┤
│              │ 会话与结构化结果              │ 会话上下文    │
│              │                               │ 真实证据      │
│              │ 需求 → 规划 → 执行 → 核验     │ 快速任务      │
│              │                               │              │
│              │ 固定输入区                    │              │
└──────────────┴───────────────────────────────┴──────────────┘
```

只面向桌面 Web。导航、会话和上下文形成稳定的三栏关系；会话内容始终是视觉中心。

## 标志性元素

“任务脉冲轨”把需求、规划、执行和核验串成一条线。阶段只能由真实 Run Event 推进；没有事件时显示等待态，失败或中断时保留已经到达的阶段，不伪造完成状态。

## 组件约束

- 高频操作不使用进入/退出动画，只提供 120–160ms 的按压反馈。
- 状态变化只动画 `transform` 与 `opacity`，并遵守 `prefers-reduced-motion`。
- 所有按钮、链接、输入和模式切换必须保留可见焦点。
- 对话恢复必须呈现 loading、empty、error、stale/syncing 和 partial 状态。
- 右侧证据卡只读取真实 Run 结果；尚无证据时展示空态，不使用示例指标。
- 结构化商品结果和约束方案继续读取后端 Artifact，不在前端重算业务结论。

## 组件策略

本阶段复用现有 React、TanStack Query 与 Lucide。原生按钮、表单和 `role="switch"` 已能满足当前交互，不额外引入只服务一个控件的依赖。后续出现对话框、弹出菜单和复杂选择器时，统一采用 Base UI 作为无样式可访问原语；通知统一采用 Sonner，长列表再引入 Virtuoso。

## 验收

- 1440×1000 与 1728×1117 桌面视口下，会话、输入区和上下文均无需横向滚动。
- 空会话、恢复失败、运行中、等待审批、已完成和结构化结果可辨识。
- 键盘可切换执行模式、选择快速任务并发送消息。
- 自动化测试、类型检查与生产构建通过。
- 使用真实浏览器保存改造前后截图，并检查控制台与请求错误。
