# 有界恢复搜索与同状态回放设计

## 目标与不变量

在既有 Adaptive Runtime 的 planning 槽位增加候选机制。在失败边界生成少量只读行动序列、实际探查、根据观察选择首步，再交给原执行链校验与执行。目标是改善失败后的行动选择，效果需独立实测。

- 继续使用 Model Gateway、ToolExecutor、原始目标与独立终止核验；探查调用计入同一个 Run 的调用、Token 与时间预算。
- 每次最多三个分支、每条最多两步，每个 Run 最多两次搜索；为正式决策和完成核验预留预算。
- 探查只允许已有只读工具或证据读取。模型无法通过候选更改目标、权限、约束、工具注册或用户确认。
- 分支观察与正式计划分开保存，分支成功不能直接完成任务。选择的首步重新通过正式执行边界，后续依据真实状态决策。
- 提案、探查结果与选择结果保存在原检查点；恢复复用已完成模型结果和工具账本。目标修订使旧选择失效。
- 同状态回放仅从显式隔离评测入口采集：冻结失败状态、历史、已读证据、业务数据、故障剩余次数及预算。每个策略使用独立数据库副本和新 Run 身份，保留来源指纹。
- 不把同起点的随机重复当作确定性因果证明；不把原始任务完成率与局部读取成功混用。缺少失败检查点时报告未采集，不用普通整任务冒充回放。
- 本阶段不开放 RSI 修改搜索结构，不自动晋升候选，不改变默认产品 Profile。

## 算法范围

第一版为有限深度的只读候选序列搜索。候选由模型生成，选择根据真实工具返回和当前目标；没有手写消费问句到动作的映射。它不是完整 MCTS，也不是能预测未知业务结果的世界模型。不同候选可共享起点，但线上只读探查期间外部数据仍可能变化；严格固定业务状态的比较发生在离线回放。

参考 [LATS](https://arxiv.org/abs/2310.04406) 的候选探索与环境反馈思路，以及 [Tree Search for Language Model Agents](https://arxiv.org/abs/2407.01476) 的环境内搜索。上述论文的结果不作为本项目收益证据。

## 接入与回放

`adaptive-recovery-search-v1` 默认两个分支、一层探查、最多两次搜索。`adaptive-recovery-control-v1` 拥有相同的错误修正资格，但搜索次数为零；二者都能在推荐引用被拒后使用原有两次修正上限。原始 `adaptive-v1` 作为第三组参考，不能把错误修正资格的差异算作搜索收益。

候选生成与基于观察的选择各占一次模型调用。探查使用独立 observation scope 并持久保存；不同搜索之间不会误用旧探查结果。无效提案或选择会记录 INVALID 并回到原决策，预算不足记录 BUDGET_SKIPPED。配置变化、取消和全局预算错误仍由 Kernel 终止。正式首步重新执行，探查与再次读取的成本均计量。

`eval/recovery_replay.py` 通过显式研究 Hook 捕获已提交失败边界。每组回放以新 Run 身份继承同一份计划、已读证据、模型游标与已消耗预算，并在独立 SQLite 中恢复所有表的数据；原 Run 不被修改。模型新调用从分叉点继续，先前响应不重新生成。剩余临时故障次数同样继承，价格变化已包含在冻结数据库中。

当前回放支持单轮任务中的超时、空结果、参数拒绝、价格变化和连续失败。运行中用户修改涉及控制命令，需要独立快照协议，本版明确拒绝该回放配置。固定业务数据不等于冻结模型随机性或供应商状态。

三组按重复编号轮换执行顺序。报告区分前缀消耗与恢复后的实际 Token、调用数和步数；探查成功不是任务成功。全部结果继续通过原任务判据、原始需求与完成审查、数据库变更检查和事件协议检查。完整度不足或成本未知时报告 INVALID。小样本一律不自动宣布稳定收益。

```bash
# 校验配置，不调用模型
venv/bin/python -m eval.run_recovery_replay

# 一次 dev 失败点采集，三组各重复两次：最多 7 次任务运行
venv/bin/python -m eval.run_recovery_replay --live \
  --output-dir research/recovery_search/smoke-01
```

`replay-spec.json` 冻结五类 test 任务、三次重复；`experiment-spec.json` 描述对应机制对照，实际回放口径由输出目录中的 `contract.json` 冻结。test 不能用于修改策略。产物包括完整失败点、原始后续运行、逐组配对结果和源码/模型配置/依赖指纹；不提交 SQLite 运行数据库。

只读工程 API 为 `/engineering/recovery-replays` 与 `/{run_id}`，仅投影样本指标、探查与正式轨迹，不返回冻结数据库或模型输入。继承工程鉴权、路径及符号链接限制。运行检查也保留 `recovery_search_*` 和 `recovery_replay_origin` 事件。
