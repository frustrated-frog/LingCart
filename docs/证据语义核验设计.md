# 证据语义核验与冲突处理 V1

## 不变量

- 来源核验、语义充分性和客观真实性是三个不同判断。模型只判断陈述能否回答政策要求；用户声明不能被升级为客观鉴定。
- 语义核验在写事务前调用现有 Model Gateway，经 RunRuntime 控制预算、超时、检查点和模型事件。事务内不调用模型。
- 输入绑定案件版本、政策身份、完整原文和已有材料指纹。事务内重新校验；并发变化拒绝提交，禁止使用陈旧核验。
- 原始证据和核验历史不可覆盖。补充或冲突不会自动撤回旧材料；撤回必须同时有用户明确意图与独立核验的原文引用。
- 只有充分且引用可校验的材料可满足声明类要求。缺失、冲突、未知、协议错误、超时均不能退回“来源通过即充分”。
- 补证、撤回、核验记录、政策重算、计划修订和关闭旧授权在同一 Tool Ledger 事务中完成。支付/退款仍要求新的明确确认。
- 现有案件计划只消费核验反馈；不增加另一套 Runtime 或自主规划循环。

## 验证计划

离线回归覆盖否定、无关材料、缺失、冲突、更正、伪造引用、跨案件引用、过期核验、模型失败、事务回滚和崩溃恢复。真实模型评测使用冻结的多轮任务和独立输出目录；默认 dry-run，只有显式 live 才调用模型。脚本模型通过不等于自然语言泛化通过。

## 实现与取舍

`prepare_after_sales_case` 和 `continue_after_sales_case` 的受信任 ToolSpec 注册事务前核验。核验输入冻结在 Checkpoint，包含完整用户原文、每条活动材料的原文、案件与订单身份、政策要求及拟撤回材料。超过上下文限制直接保留 UNKNOWN，不把截断的原文当完整证据。独立调用使用 `evidence_verification` 职责，可通过 `LLM_EVIDENCE_VERIFICATION_MODEL` 覆盖模型，仍共享 Gateway 和 Runtime 的预算、超时与降级链。

verification 槽位通过 `assess_evidence` 提供替换入口。既有两个验证机制升级为版本 2，增加源码指纹；Stable Kernel 校验所有返回值。模型不读取前一个模型的推理或学习 Playbook，也不能提交可信来源、审批结论或证据状态。

结果为 SUFFICIENT、INCOMPLETE、IRRELEVANT、CONFLICT 或 UNKNOWN，保留引用、缺失信息、说明与具体问题。SUFFICIENT 至少需要匹配证据类型的原文引用，且不能同时存在待澄清项；其他结果必须附追问。语义选择本身仍是概率判断，这些结构校验不保证模型永不误判。

新表 `after_sales_semantic_assessments` 保存不可变核验输入、输出、Prompt 指纹、案件版本和模型调用游标。材料变更与 EVIDENCE_SEMANTIC_ASSESSED 事件、政策裁决、计划修订、旧授权关闭一起提交。恢复时复用已经保存的核验并恢复模型游标，不重复调用或写入；事务后崩溃继续由 Tool Ledger 重放。查询时还检查原始 Run 内容，防止选中短句仍然匹配、但完整原文已改变时沿用旧语义。

CasePlan 继续做确定性的依赖修订。未满足要求使用核验返回的问题；目标指纹忽略核验记录的随机编号，保留内容没有改变的目标。首次建案保留既有 ISSUE_DESCRIPTION 类型映射，后续材料按政策要求分类；本轮没有扩展多材料自动拆解。

## 兼容策略

数据库仅新增表，旧证据和裁决不回填伪造结果。没有语义核验的声明类材料保持未满足；未提交案件的旧裁决和计划显示陈旧，需通过继续案件重新核验，旧确认不能直接提交。已提交及终止案件的历史保持可读。跨部署恢复仍要求原 Harness 与源码指纹匹配，不自动把旧运行切换到新版核验。

撤回不会被“最新一句”自动触发。输入必须指定既有材料，独立核验也必须找到明确撤回/替换意图。缺少此依据返回 `EVIDENCE_WITHDRAWAL_UNCONFIRMED`，不修改证据。单纯冲突作为新材料保留，关闭旧审批并等待澄清。模型失败会持久化 UNKNOWN 与机器错误码，不恢复来源校验捷径。

## 评测边界与命令

`eval/evidence_semantic_tasks.json` 冻结 10 个案例、22 轮材料，3 个 dev 案例、7 个 test 案例，每个分组重复 3 次。覆盖否定、补充、冲突、明确更正、跨订单与对象混淆、指令注入和未授权撤回。期望标签不进入模型输入。

本轮新增的是**核验组件实验**，契约位于 `research/evaluations/evidence-semantic-v1/experiment-spec.json`，使用专门的严格 schema，避免混入要求完整 Harness Profile 的端到端实验列表。对照是只读实现的 `provenance-reference-v1` 与真实 `evidence-semantic-v1`；旧来源规则不注册为产品工具或安全降级路径。两组使用同一冻结材料，撤回结果影响后续活动材料，各轮保持可追溯。尚未执行真实模型时，不声称泛化或端到端收益。

```bash
# 默认只校验任务集指纹、分组和调用预算，无模型调用
venv/bin/python -m eval.run_evidence_semantic_eval
venv/bin/python -m eval.run_evidence_semantic_eval --split test

# 显式 live，使用全新的输出路径，最多 42 / 90 次模型尝试（dev / test）
venv/bin/python -m eval.run_evidence_semantic_eval --live --split dev --output output/evidence-dev-001.json
venv/bin/python -m eval.run_evidence_semantic_eval --live --split test --output output/evidence-test-001.json
```

报告记录逐轮输出、原始模型响应、脱敏模型事件、错误接受、错误撤回、多次重复稳定性、无谓追问、真实调用次数、Token 与延迟。缺少 usage 时 Token 为 null。原始样本逐条落入 `.samples.jsonl`，中断和负结果都保留；文件只允许新建。Gate 要求零错误接受、零未授权撤回、零协议错误、可用性无失败、正确率和稳定性不退化，并有错误接受改善。通过这个 Gate 也不能自动 promoted，因为本轮未比较完整对话理解、工具选用或端到端任务完成率。

图片/OCR、客观事实鉴定、人工裁决队列、自主行动选择与通用矛盾逻辑证明仍不在本轮范围内。
