# 证据语义核验与冲突处理 V1

## 不变量

- 来源核验、语义充分性和客观真实性是三个不同判断。模型只判断陈述能否回答政策要求；用户声明不能被升级为客观鉴定。
- 语义核验在写事务前调用现有 Model Gateway，经 RunRuntime 控制预算、超时、检查点和模型事件。事务内不调用模型。
- 输入绑定案件版本、政策身份、完整原文和已有材料指纹。事务内重新校验；并发变化拒绝提交，禁止使用陈旧核验。
- 原始证据和核验历史不可覆盖。补充或冲突不会自动撤回旧材料；撤回必须同时有用户明确意图与独立核验的原文引用。
- 只有充分且引用可校验的材料可满足声明类要求。缺失、冲突、未知、协议错误、超时均不能退回“来源通过即充分”。
- 补证、撤回、核验记录、政策重算、计划修订和关闭旧授权在同一 Tool Ledger 事务中完成。支付/退款仍要求新的明确确认。
- 现有案件计划只消费核验反馈；不增加另一套 Runtime 或自主规划循环。

## 验证计划

离线回归覆盖否定、无关材料、缺失、冲突、更正、伪造引用、跨案件引用、过期核验、模型失败、事务回滚和崩溃恢复。真实模型评测使用冻结的多轮任务和独立输出目录；默认 dry-run，只有显式 live 才调用模型。脚本模型通过不等于自然语言泛化通过。
