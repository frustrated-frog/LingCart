# 恢复搜索门控与严格候选协议

## 动机与不变量

首轮 dev 回放没有证明搜索收益：简单超时后原始决策已经能恢复，额外提案和探查增加成本；另一次无效提案没有保留原始响应，不能推断其具体原因。本阶段保留 v1 与旧产物，新增版本化候选，验证按需分配搜索预算的假设。

- 搜索只在原 Adaptive planning 槽位执行，沿用 Kernel 的工具、权限、预算、恢复和完成核验。不会修改业务目标或提高调用上限。
- 默认连续两个失败决策边界、期间没有新增有效正式观察时才搜索；门控本身不调用模型。阈值是计算资源调度参数，不是问句到业务动作的规则。
- 门控记录持久化且幂等；重复进入同一检查点不增加失败计数。目标或约束修订、新的有效正式观察会重置计数。空结果、失败探查和重复读取相同内容不算新增有效观察。
- 探查分支不进入正式证据；每个模型响应与工具执行继续使用原账本。已开始的搜索恢复时不重新判断门控。
- 候选协议根据现有只读工具 schema 构造；工具参数和证据读取是分离的结构。分支编号由程序分配。解析、完整预算与归一化重复校验在任何探查前完成，不增加格式修复重试。
- 保留所有无效提案、门控跳过和失败；小样本不宣称稳定收益，不自动晋升，不开放 RSI 修改搜索结构。

## 对照与交付

新增 `adaptive-recovery-eager-v2` 与 `adaptive-recovery-search-v2`，两者使用同一 v2 协议、分支数、深度和预算，只改变门控阈值（1 与 2）。无搜索的 `adaptive-recovery-control-v1` 为第三组参考。

回放合同显式冻结三个 Profile；旧合同继续可读。训练 smoke 包含简单超时和连续工具失败，每个失败点三组各两次，保留前缀和恢复后成本。正式 test 不参与本次调参。

页面从真实合同读取策略身份，并展示每次门控的失败计数、阈值、放行或延后原因；门控跳过不能显示成探查成功。真实运行、余额不足与成本完整性修复见[恢复搜索门控真实验证记录](恢复搜索门控真实验证记录.md)。

```bash
# 默认只校验，不调用模型；最大两次采集加十二次后续运行。
venv/bin/python -m eval.run_recovery_replay \
  --spec research/experiments/recovery-search-v2/smoke-spec.json

# 显式真实模型评测，输出目录必须全新。
venv/bin/python -m eval.run_recovery_replay \
  --spec research/experiments/recovery-search-v2/smoke-spec.json \
  --live --output-dir research/recovery_search/gated-smoke-01
```

本版“新增有效观察”是去除 observation 时间/引用元数据后，不重复的成功正式观察内容；不是模型置信度或信息熵估计。它可以识别同一工具重复读取相同内容，但不宣称能跨不同工具自动识别语义相同的内容。搜索探查不参与该计算。门控只分配预算，仍可能延后本来有益的搜索，需要对照检验。
