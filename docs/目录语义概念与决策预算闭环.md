# 目录语义概念与决策预算闭环

## 目标

本轮改造解决的不是“少调用一次模型”这一表面问题，而是把目录语义从规划模型的临时猜测中剥离出来。模型仍负责理解用户说的是什么，Stable Kernel 负责证明这个语义如何映射到当前目录字段，独立审查模型负责确认映射没有改变用户原意。

完整链路为：

`用户原文 -> 冻结语义概念 -> 真实目录观察 -> codec 映射提案 -> 独立映射审查 -> 有界动作面 -> 新鲜度核验 -> 独立完成审查`

任何一步缺失都不能把映射或推荐标记为已完成。

## 三层职责

### 语义层

`Constraint.catalog_concept` 保存模型对用户语义的声明，包括：

- 注册表 schema revision；
- 稳定 concept ID；
- 极性或范围操作符；
- 与物理目录表示无关的 canonical value。

模型只能从注册表公开的概念菜单中选择。注册表以外的语义继续走证据驱动的普通规划路径，不能因为字段名称相似、某个字段恰好唯一，或字符串有重叠就自动绑定。

### 编码层

`src/catalog_concepts.py` 中的注册表是不可变、内容寻址的工程产物。每个概念拥有独立 codec，codec 明确声明：

- 可用操作符；
- canonical value 集合或数量单位；
- 物理字段路径；
- 目录中的存储表示；
- 对已观察值的兼容性检查。

枚举 codec 要求已观察值属于冻结编码域；数量 codec 要求单位和格式可无损解析。schema revision 不匹配、字段缺失、未知枚举、单位漂移或非标量结果都会关闭自动路径，不会降级成猜测。

### 审查与提交层

自动 resolver 只读取经过工具结果校验的 `binding_evidence_access`。这份内核投影与模型的 `evidence_access` 分离：它可以支撑映射提案和独立审查，但不能让规划模型凭未读记录直接推荐商品。

多个待绑定概念采用全有或全无事务。事务冻结：

- 原目标与目标版本；
- 变更前后映射指纹；
- codec 注册表完整身份；
- 提案内容；
- 观察证据摘要；
- 独立审查引用；
- 应用后的 binding revision。

事务状态为 `PROPOSED -> APPLIED` 或 `PROPOSED -> REJECTED`。检查点在审查前持久化提案；进程恢复时复用同一事务和已保存模型响应，不能重复增加映射版本。

## 六次模型调用闭环

单目标、已注册概念的选购任务在最大六次模型调用内采用以下顺序：

1. 规划模型声明完整目标与语义概念；
2. 独立模型审查目标覆盖、概念选择和极性；
3. 规划模型执行一次目录读取；
4. 内核生成映射提案，独立模型审查映射；
5. 规划模型从满足硬约束的已读候选中做推荐；
6. 独立模型审查最终证据闭包。

这里没有删除审查。节省的是“模型再次解释已经冻结的字段编码”和“已有合格候选时仍继续比较或重规划”的冗余轮次。

当且仅当以下条件同时成立时，运行时把动作面收敛为 `recommend / clarify / finish`：

- 只存在一个推荐目标，且没有显式对比目标；
- 自动映射事务已经由独立审查批准；
- 所有适用硬约束都有可执行谓词；
- 下一轮上下文中存在至少一个完整、已读且机械校验通过的候选；
- 恰好还剩一次规划调用和一次完成审查调用。

候选集合只表示“满足条件”，不包含排序策略，也不会替模型选择商品。最终推荐仍会重新读取价格、库存和规格。

## 审计指纹

需求、映射和完成审查均记录审查 basis 指纹。完成审查不再绑定整个探索计划，而是绑定目标账本引用的传递证据闭包：选品凭证、其依赖的商品观察，以及读取证据的来源记录。无关探索步骤不会伪装成完成依据；任何实际交付证据变化都会使完成审查失效。

## 失败与回退

- 没有目录观察：继续规划读取，不生成提案；
- 部分概念可解析：整批不提交，避免半绑定目标；
- codec 与观察不兼容：记录 `constraint_binding_unresolved`，回到规划路径；
- 独立审查拒绝：保留原始目标和旧映射，记录拒绝事务；
- 用户在审查期间修改目标：旧事务因 revision 冲突不能提交；
- 进程在提案后中断：恢复同一内容寻址事务，不重复规划或递增 revision；
- 最终事实变化：新鲜度核验拒绝推荐，完成审查不能覆盖失败。

## 扩展新论文机制时的边界

新的语义解析、ontology induction 或 schema alignment 论文机制可以生成候选 concept 或 codec 草案，但不能直接进入生产注册表。进入 Stable Kernel 前仍需版本化人工审查、固定离线样本、兼容性测试和新的 schema revision。学习机制不能在运行中修改 codec，也不能放宽独立审查、预算和新鲜度门禁。
