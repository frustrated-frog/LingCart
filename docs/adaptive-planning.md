# 自主选购与复合任务：模型逐步决策与执行核验

`src.adaptive.run_adaptive` 使用模型驱动的循环。`auto` 模式的直接查询路径不变；选择 `adaptive` 后，购物目标无论是否能被关键词识别，都必须由模型理解和决策。没有可用模型时返回 `FAILED / MODEL_UNAVAILABLE`，回复明确说明“自主模式未执行”，`autonomous_executed=false`，不执行购物工具或生成推荐。

## 决策协议

`src/adaptive_decision.py` 定义严格 JSON 协议。模型首次提交 `goal`，包括逐项目标 `objectives`、目标摘要、硬约束、软偏好和不确定性。每个目标有唯一编号、用户原文 `source_quote`、完成类型与必要的订单/问题等对象信息；不能省略目标清单或默认为单一选购。每个硬约束包含用户原文、语义说明、目录字段、操作符与值。否定范围由模型理解；执行层不再扫描“主动降噪 / 降噪”等关键词，也不将软偏好转换成硬条件。当前请求和运行中补充要求保持原文，确认偏好单独提供给模型。

执行层仅检查引用是否存在、字段与类型是否有效，并按结构化谓词核验商品。支持相等、不等、包含、不包含、成员关系和数值上下限。缺失字段不能证明否定条件；无法从目录证明的条件用 `field=null` 表达，不能通过推荐核验。数值规格只接受单个数值及单位，不猜测范围或营销描述。模型有不确定性时必须先发出澄清。同一用户需求版本内的硬约束不可被模型自行放宽；新用户指令触发重新理解，旧目标和观察保留在记录中。

模型每次只提交一个动作：

- `tool`：调用授权只读工具，参数和商品/订单编号接受运行时验证。
- `revise_plan`：修改后续计划说明及原因；计划是建议，不是批量待执行队列。
- `clarify`：向用户提出问题，返回 `WAITING_CLARIFICATION`。
- `recommend`：提交对应的目标编号、商品编号、选择理由和包含该商品的观察步骤引用，进入推荐核验。
- `complete`：对每个目标提交 `objective_id / evidence_refs` 完成声明，进入逐项完成核验。
- `finish`：说明无法继续，返回 `PARTIAL` 或 `FAILED`，不冒充成功推荐。

每次工具观察、工具错误、推荐核验或完成声明失败后，执行层重新调用模型。没有预设搜索→比较→最低价选择路径。模型可以更换搜索词、重新读取、比较其他候选、修改计划、提问或停止。只有所有声明目标的证据均通过执行层核验，才能使 `all_goals_satisfied=true`。

## 复合目标与完成契约

例如“推荐预算500的耳机，并查询订单1001状态”，模型应声明选购和订单查询两个目标；代码不为它生成工具顺序。`objective_ledger` 由运行时维护，每项保存状态、证据引用和失败原因，完整进入下一轮模型输入、检查点和 Agent Lab。模型只能提交证据，不能直接写入完成状态，不能通过修改计划说明删除未完成目标。

单一选购仍可在 `recommend` 核验后完成；复合请求中的推荐仅完成该选购项，继续交回模型。模型决定何时提交 `complete`，必须逐项引用已成功执行的观察。订单目标核对查询类型和确切订单编号；FAQ 核对原问题；指定商品比较核对候选集合；推荐必须引用同一需求版本、同一目标的成功 `select_product` 核验步骤。失败查询、错订单、仅有搜索结果、其他目标的推荐或未读取的归档观察，都不能充当完成证据。遗漏、类型或对象不符会反馈给模型自行处理。

全局硬约束作用于全部推荐，各选购目标也可有专属约束。多个推荐有各自的核验记录。复合任务最终完成前，运行时逐一重新读取选中商品，防止选购后执行其他查询期间价格或库存已变；刷新失败返回模型，保留其他已核验结果。部分完成时回复列出已核验事实和未完成目标，不将旧价格包装为最终推荐。

当前完成类型覆盖推荐、订单/支付状态、订单详情、物流、退款资格、FAQ 和商品比较；无法用现有证据证明的目标以 `unresolved` 保留并澄清，不能宣布成功。目标的语义提取仍由模型负责：执行层能阻止已声明目标漏做，不能证明模型已完整理解自然语言、没有在首次声明时漏掉隐含需求。脚本测试不代表真实模型已经具备这项理解能力。

## 最终证据与时效

推荐前通过 `ToolExecutor` 独立读取商品，关闭库存和预算过滤，核验确切商品编号、有效价格/库存、库存大于零及全部硬约束。引用中的价格、库存、类别、规格、名称、摘要必须与新读取一致。任何变化都会生成 `RECOMMENDATION_VERIFICATION_FAILED`，将最新商品证据和失败项返回模型；代码不会自动改选或放宽条件。

模型可以引用失败核验产生的新观察重新提交，也可以选择其他候选或询问用户。最终回复使用新核验的价格、库存和时间，并保留模型的选择理由及引用。观察包含事件引用、时间戳和内容摘要哈希；哈希是观察内容标识，不是商品数据库的事务版本。推荐仅保证核验时点的事实，不预留库存；下单/支付仍须走独立审批和业务校验。

## 安全、预算与恢复

所有工具经现有 `ToolExecutor` 执行，显式只读策略、参数、权限和共享模型/工具/时间/token 预算继续生效。每个工具动作和推荐占用步骤预算；计划说明最多修改两次。工具重试有界，超时等失败可以作为观察交回模型，预算和权限失败直接终止。模型不能通过计划获得支付或退款授权；这些请求和待确认动作沿用既有审批路径，结果标明 `execution_mode=auto`。

自主状态的 `schema_version=5` 检查点保存已接受决策、模型游标、待执行动作、逐项目标账本、用户需求版本、计划说明和完整观察；外层运行时快照版本不变。工具动作以需求版本和步骤编号隔离读取：中断恢复重用该动作的账本，不重选业务步骤；模型响应已经落库而决策尚未保存时，重用相同输入的模型响应。

最终推荐核验每次尝试使用新读取 scope，包括复合完成及终态提交前崩溃后的恢复。已经完成的核验观察保留，新尝试重新检查；中断遗留的未完成刷新会明确取消，不能把恢复账本当作当前商品状态。旧版自主检查点（包括缺少逐项目标契约的版本2）明确返回 `ADAPTIVE_CHECKPOINT_INCOMPATIBLE`，要求新建任务，不替模型猜测缺失目标。

Steering 或取消在模型调用后、动作执行前及最终完成前再次检查。模型推理期间到达的新用户指令会使旧决策失效；Steering 清空工作笔记、目标账本和旧计划说明，由模型重新理解。此前已核验的推荐不能直接作为新需求的完成证据。完成事件与最终结果仍由持久运行入口原子提交。

## 按需证据与工作笔记

决策输入由 `ContextEngine.decision_messages` 按实际字符预算构建，并计入运行时注入的偏好。当前请求、结构化硬约束、计划说明、失败反馈和模型工作笔记保持完整。完整工具结果留在运行检查点的计划中；模型上下文优先保留最新观察，其余记录仅在完整放得下时加入。放不下的观察提供步骤引用、原观察时间、商品编号与数量，不截断规格，也不挑选或排序候选来替模型决策。

模型新增 `inspect` 动作：`evidence_ref` 为本次运行的步骤编号，`offset` 为非负偏移，`limit` 为 1–3 条。模型可以选择任意页，按 `evidence_page.next_offset` 继续查看。读取返回完整原始记录，明确 `refreshed=false`；不会重新查询业务数据库，也不把历史价格标为当前价格。未知引用和非法分页作为反馈交回模型。

索引中的编号不能单独支持推荐。执行层记录模型实际看到过的完整商品记录；未读取证据的推荐会被拒绝并反馈 `UNREAD_RECOMMENDATION_EVIDENCE`，模型可以再选择读取。推荐最后仍经过独立的实时核验。归档读取占用步骤和模型调用预算，不计为业务工具调用；没有额外权限，不能跨运行读取。

`working_memory` 是模型可选更新的有界工作笔记，保存候选判断摘要、现有证据引用和待解决问题。它随检查点恢复，在用户 Steering 后清空，不能修改硬约束、充当商品证据或写入跨会话长期偏好。Agent Lab 可查看工作笔记及已读取证据；事件记录包括 `evidence_context`、`evidence_read` 和未读证据导致的 `decision_rejected`。

这是完整记录与引用之间的上下文调度，不宣称具有任意长度的语义压缩能力。淘汰旧历史后，当前用户目标、证据索引和工作笔记的最小集合仍超预算时，继续明确返回 `CONTEXT_BUDGET_EXHAUSTED`；单条超大记录不会被悄悄截断来完成推荐。

## 2026-10-15 评审整改：原始需求的独立审查

首次目标接受前，`request_audit.review_request` 发起独立模型调用，从原始用户请求与人类历史枚举要求，再检查模型目标是否覆盖，以及否定极性、金额方向、数量和排除条件是否表达正确。执行层只检查审查协议、原文引用、目标/约束引用及版本绑定，不增加自然语言关键词推断。没有有效审查不能开始执行该目标。模型主动澄清时允许不执行审查，但不能报告完成。

审查返回 `APPROVED / REVISE / CLARIFY`，记录 `request_audited` 事件、原文片段、解释、对应目标与谓词、问题和需求摘要哈希。审查拒绝会反馈给规划模型，后者决定修复完整目标或向用户澄清。首次遗漏订单目标、反转“不要主动降噪”的脚本反例已覆盖。这里的“独立”指单独调用、不同任务提示、没有规划模型的对话/工作笔记，并不要求另一个供应商，也不保证两个模型不会共同误判。

最终完成前再次独立核对原始需求和真实完成证据，审查与需求版本、目标及证据内容哈希绑定。最终审查失败不能降级为通过，已有业务结果保留。所有审查调用、重试和修复均计入运行时模型、时间和 token 预算。协议或参数可修复错误最多修复两次，不重置已消费预算，不授予写权限。审查不可用、格式持续错误或预算不足时明确失败。

自主检查点为 `schema_version=5`；旧版没有需求审查记录的活动任务拒绝猜测迁移，历史已完成记录保留。恢复和 Steering 仍受原账本及审批边界约束；恢复后的最终审查不能复用基于旧商品观察的响应。

## 政策证据、历史预算与演示人工请求

`answer_faq` 返回结构化的 `status / question / answer / policies / data_source`。有效政策包括 `policy_id / version / text / source`。`NOT_FOUND`、没有政策依据、旧版通用字符串兜底和错误问题的答案，不能作为完成证据。工具成功返回只说明调用结束，未证明用户问题已解决。政策检索仍使用本地演示文本，语义相关性还需模型审查，不能等同正式知识库问答能力。

旧历史在预算不足时按完整消息从旧到新淘汰，记录被省略的消息序号；当前请求、目标、硬约束不破坏性截断。工具原始观察继续保存在检查点，需要时通过已有 `inspect` 读取。被省略历史不作为当前已读证据；缺乏指代依据时应澄清。最小必要上下文仍放不下时继续显式报预算错误。

人工请求写入 `support_tickets`，按运行编号幂等保存到本地 `QUEUED` 演示队列。返回 `mode=DEMO / delivered=false / escalated=false`，界面不会声称已对接真人或承诺通知。暂未接入真实客服、接单与通知服务。

## 2026-10-15 真实故障修复：原意与执行映射分离

真实模型曾将用户“不要主动降噪”映射为目录中不存在的英文字段。完整锁死执行谓词会阻止它看到中文目录后修正映射，而直接允许修改目标又可能放宽用户条件。现在保留最初接受的 `goal`、原文引用、目标集合、硬条件描述；将可修订的字段、操作符与值编码保存在 `constraint_bindings`，使用独立 `binding_revision`。

模型通过 `refine_constraints` 提交现有条件的 `constraint_ref / field / op / value / evidence_refs / reason`。引用只能指向实际读过的商品记录，新字段必须真实存在；代码不根据中文关键词生成映射。独立模型从原文核对有效谓词是否保留同一要求。放宽预算、反转排除、丢弃条件、增加无依据要求或无法证明等价的提案不能批准。软偏好用于选择理由，不可变成硬过滤。

初始 `field=null` 可表示尚待目录发现的编码。用户意图清楚时，Agent 可以先查证据再提交映射；不会仅因目录编码未知就要求用户解释数据库字段。真正不确定的用户意图仍澄清，首次澄清也可不伪造结构化目标。查询、比较、重查、映射修订、选择、澄清和结束的顺序均由模型决定。

映射审查与原始目标、用户需求版本、映射摘要、映射版本绑定。批准后旧推荐账本失效，旧版本 `select_product` 不能作为当前完成证明；服务查询证据保留。推荐与复合完成使用当前有效谓词、最新价格和库存，最终审查同时绑定有效映射和完成证据。重复提交已生效映射会获得明确反馈，不重新消耗审查调用。映射过程和审查记录在 Agent Lab 可见。

版本5检查点保存映射、版本与独立审查。版本4可确定性补上空映射及版本0，原目标和已完成业务观察不改写；更早、缺少需求审查契约的检查点仍拒绝猜测迁移。中断后恢复映射和已批准审查；审查期间的新用户指令会丢弃旧提案。所有映射都属于当前运行，不能读取其他任务证据。

自主预算统一为最多16次模型尝试、16次实际工具调用、16个步骤、128000输入token、8000输出token、90秒总时限、30秒单次时限和18000字符上下文；界面、持久入口与自主评测使用同一配置。显式传入的更小预算仍有效，恢复保持原预算与已消费用量，不因修订重置。默认快速业务路径的原预算保持独立。

目标构建说明只在尚未接受目标时提供。后续上下文显示生效谓词和原始条件描述，避免模型反复修正已经生效的映射。最新完整观察先于旧历史；如果刚请求的证据页可在淘汰旧消息后放下，就完整提供，防止“读取后又立即归档”的无进展循环。过大记录继续通过分页读取，不截断用户原文或商品规格。

这些措施提供可观察、可恢复的自主执行机制，不保证模型的每次语义判断都正确。真实测试必须另外检查人工标注约束、目标覆盖、环境漂移和最终数据库事实；不能仅用模型审查通过率衡量能力。
