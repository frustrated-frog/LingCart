# 程序图状态转移预演设计

## 目标

PG V6 在现有 V4 在线状态条件机制和 V5 离线贡献记忆之上增加有界前瞻规划。实现仍属于 Harness 的 `context` 槽位：它生成可审计的候选建议，不拥有工具执行权，也不改变 Stable Kernel。

## 执行链路

1. `build_trajectory_state` 从持久状态、计划、预算和事件构造当前状态。
2. V4 定位器与三值条件协议选出当前被证据证明为 `TRUE` 的一跳边。
3. `plan_preplay` 从这些边开始执行最多三层 Beam Search。
4. 每次转移只投影 `action + outcome=UNKNOWN`；目标、证据和权威业务事实不发生变化。
5. 路径效用由目标推进启发值、信息价值、历史可靠性、成本与不确定性组成；分值不解释为概率或因果收益。
6. 最高分路径的第一步写入确定性指导契约，其余步骤全部标记为需要重新核验。
7. 工具真实返回后，V4 信息增益协议生成 `pg_action_outcome`；V6 再生成幂等的 `pg_prediction_outcome`，下一次决策重新预演。

## 持久化与恢复

`pg_guidance.preplay.plan_id` 覆盖图身份、状态指纹、搜索参数和候选路径身份。相同决策键复用既有事件。预测结果使用 `review_id + outcome_id + comparison_id` 生成幂等身份；恢复时不会重复写入偏差证据。

## 安全不变量

- 预测不能成为 `objective_ledger` 的证据引用。
- 预测不能跳过 ToolExecutor、独立请求审查、确认或预算检查。
- 未知工具结果不得推断为成功或非空。
- 未来路径不得提前执行。
- Product Profile 仍拒绝加载该候选机制。

## 当前限制

行动转移模型是冻结的类型级启发式表，尚未根据真实轨迹校准。当前离线 Gate 只验证协议正确性；在冻结留出集完成真实模型对照前，不宣称成功率或成本收益。
